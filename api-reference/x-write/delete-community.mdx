## Delete a community cautiously

Use this route only for a community managed by the connected account. Confirm
the numeric community ID before approval. Save the community name,
description, rules, and required records first.

Create a unique idempotency key for this deletion. Reuse it only after a
transport failure. Never share it with a membership or settings action.

Require explicit review for:

- Removing a test community after validation.
- Retiring a community that has completed its purpose.
- Correcting a community created from the wrong account.
- Recording the owner, reason, and approval reference.

Treat the deletion as irreversible within this API workflow. Do not report
success from the request alone. Store the returned action ID and lifecycle
state. Poll the status route when processing remains asynchronous.

## Headers

<ParamField header="x-api-key" type="string" required>
  Your API key. Session cookie authentication is also supported. Generate a key from the [dashboard](https://xquik.com/dashboard).
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique key for this intended write. Reuse it only for an exact network replay.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  The ID of the community to delete.
</ParamField>

## Body

<ParamField body="account" type="string" required>
  The connected X account that owns the community. Must be a username you have connected to your Xquik account.
</ParamField>

<ParamField body="community_name" type="string" required>
  The name of the community. Required as a confirmation safeguard to prevent accidental deletion.
</ParamField>
