## Prepare a profile banner

Use the banner route for the wide header image. Choose a direct file or a
fetchable HTTPS URL. Keep the source exclusive.

Preview the banner at desktop and mobile widths. Profile controls can cover
parts of the artwork. Keep critical text and faces away from those areas.
Confirm JPEG or PNG format and the 2 MB maximum.

Assign one idempotency key to the approved banner. Create a new key after any
image revision. Store the connected account, redacted source reference, action
ID, and lifecycle state. Remove query parameters before retaining a source
URL.

Banner workflows commonly include:

- Launching reviewed campaign artwork on one account.
- Restoring a standard header after an event.
- Applying localized artwork after regional approval.
- Preventing overlapping banner updates from separate queues.

Use the avatar route for the square profile image. Use profile update for text
fields such as biography and location.

## Headers

<ParamField header="x-api-key" type="string" required>
  Your API key. Session cookie authentication is also supported. Generate a key from the [dashboard](https://xquik.com/dashboard).
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique key for this intended write. Reuse it only for an exact network replay.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Use `multipart/form-data` for file uploads or `application/json` for URL uploads. Most HTTP clients set the multipart boundary automatically.
</ParamField>

## Body

<ParamField body="account" type="string" required>
  X username or account ID of your connected account to act as.
</ParamField>

<ParamField body="file" type="binary">
  Multipart upload file. Required unless `url` is provided. Accepted formats: JPEG, PNG. Maximum file size: 2 MB.
</ParamField>

<ParamField body="url" type="string">
  JSON upload URL. Required unless `file` is provided. Must be an HTTPS URL that Xquik can fetch directly.
</ParamField>
