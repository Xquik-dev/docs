## Choose Unretweet

Use this route to remove your account's repost of one tweet. It does not remove likes, original tweets, follows, or profile changes. Store the write-action ID before continuing the workflow.

## Remove One Repost Without Changing Follows

Send the original tweet ID and the connected account username. The route
removes that account's repost relationship only. It does not unfollow the
author, unlike the tweet, or delete the author's post.

Use a unique idempotency key for the removal intent. Store the returned action
ID and status URL before retrying. Poll until the action becomes terminal, then
confirm the repost removal from the final action result.

Do not use this route for quote tweets. A quote tweet is a separate published
post with its own tweet ID. Remove it through the supported tweet deletion
workflow when that behavior is required.

Keep the connected account and tweet ID in the audit row. They identify which
repost changed. The [Unfollow User](/api-reference/x-write/unfollow) route
changes a profile relationship and serves a different workflow.

## Reverse a repost with traceability

Use this route to remove one repost from a connected account. Match the tweet
ID against the account’s repost record first. Keep the original approval
reference beside the removal request. This makes campaign cleanup auditable.

Generate a new idempotency key for the removal. Do not reuse the key from the
original repost. Reuse the removal key only after a timeout or dropped
connection.

Typical repost-removal workflows include:

- Ending a time-bounded promotion.
- Correcting an accidental repost from the wrong account.
- Removing content after a policy or legal review.
- Reconciling a campaign ledger with the account timeline.

Record the returned action ID and lifecycle state. Keep failures separate from
completed removals. Poll the action status route if processing continues in
the background.

## Confirm Repost Removal

Store the Tweet ID, connected account ID, action ID, and idempotency key. Poll the write status until it reaches a terminal state.

A queued response does not prove removal. An already-removed result means the repost state converged.

Refresh the account timeline only when downstream work needs current proof. Preserve generic errors and request IDs. Then retry the same Tweet.

This operation changes only repost state. It does not change follows, likes, replies, or bookmarks.

| Repost removal column | Source | Cleanup rule |
| --- | --- | --- |
| `acting_account` | Request `account` | Match the account that owns the repost. |
| `tweet_id` | Path `id` | Match the exact reposted Tweet ID. |
| `original_approval_reference` | Repost ledger | Preserve why the repost originally occurred. |
| `removal_reason` | Workflow value | Preserve why the repost should end. |
| `idempotency_key` | Request header | Use a new key, separate from the original repost. |
| `write_action_id` | Response `id` | Store the durable removal action. |
| `status` | Response `status` | Keep pending, completed, and failed removals distinct. |
| `terminal` | Response `terminal` | Update the campaign ledger only when `true`. |
| `requested_at` | Integration timestamp | Keep cleanup time separate from repost time. |

| Removal outcome | Evidence | Campaign update |
| --- | --- | --- |
| Queued | `terminal: false` | Poll `statusUrl`; keep the repost active locally. |
| Completed | Terminal success | Mark the repost removed for this account and Tweet ID. |
| Already removed | Converged terminal result | Mark the desired state without another request. |
| Retryable failure | `safeToRetry: true` | Preserve the receipt and follow lifecycle guidance. |
| Final failure | Terminal failure | Store the error and keep the prior repost state. |
