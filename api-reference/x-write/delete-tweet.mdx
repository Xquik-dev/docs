## Delete a tweet with an audit trail

Use this route only after identifying the exact published tweet. Save its
tweet ID, author account, text, and approval reference before deletion. The
tweet may become unavailable after the action succeeds.

Create a dedicated idempotency key for this deletion. Reuse that key only
after an interrupted response. Never reuse a create-tweet key for deletion.

Deletion workflows should include:

- Confirming the connected account owns the target tweet.
- Showing the final tweet text during approval.
- Saving any required compliance record before removal.
- Recording the returned action ID and final lifecycle state.

Treat deletion as irreversible within this API workflow. A replacement tweet
receives a different tweet ID. Do not mark the original tweet deleted until
the action response confirms completion.

| Tweet deletion record | Request or response source | Completion rule |
| --- | --- | --- |
| Tweet ID | Path `{id}` | Preserve the exact post identifier. |
| Acting X account | Request `account` | Confirm tweet ownership before deletion. |
| Tweet text | Pre-deletion lookup | Save the approved post content first. |
| Idempotency key | Request header | Reuse it only for an exact replay. |
| Write action ID | Response `id` | Poll the matching lifecycle record. |
| Lifecycle state | Response `status` and `terminal` | Stop only after a terminal state. |
| Deleted tweet | Response `tweetId` or `targetId` | Require the requested tweet ID. |
| Removal proof | Tweet lookup after success | Confirm the post is unavailable. |

## Choose Tweet Deletion, Unlike, or Unretweet

Use tweet deletion only when the connected account owns the published post.
It removes that post. It does not merely reverse an engagement action.

Use [Unlike Tweet](/api-reference/x-write/unlike) to remove one account's like.
Use [Unretweet](/api-reference/x-write/unretweet) to remove one account's
repost. Both actions preserve the source tweet.

| Cleanup intent | API route | What changes |
| --- | --- | --- |
| Remove an owned post | `DELETE /x/tweets/{id}` | The connected account's tweet becomes unavailable. |
| Remove a like | `DELETE /x/tweets/{id}/like` | Only that account's like is removed. |
| Remove a repost | `DELETE /x/tweets/{id}/retweet` | Only that account's repost is removed. |
| Remove a reply | `DELETE /x/tweets/{id}` | The owned reply tweet is deleted by its own ID. |

Never delete the source tweet when a campaign only needs engagement cleanup.
Confirm the route and intended state during approval.

## Preserve Tweet Deletion Evidence

Read [Get Tweet](/api-reference/x/get-tweet) before deletion. Save the tweet
ID, author ID, text, creation time, media, and conversation ID when returned.
Keep the approval reference beside this snapshot.

After terminal success, request the same tweet ID again. Store the lookup time
and result. Do not treat a client timeout as deletion proof. Poll the original
write action before replaying the request.

A replacement post receives another tweet ID. Keep the deleted ID in the
audit record. This prevents incorrect joins with the replacement. It protects
analytics, reply archives, and moderation queues.

## Headers

<ParamField header="x-api-key" type="string" required>
  Your API key. Session cookie authentication is also supported. Generate a key from the [dashboard](https://xquik.com/dashboard).
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique key for this intended write. Reuse it only for an exact network replay.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  The ID of the tweet to delete. Must be a tweet owned by the specified connected account.
</ParamField>

## Body

<ParamField body="account" type="string" required>
  X username or account ID identifying which connected X account owns the tweet. The `@` prefix is automatically stripped if included.
</ParamField>
