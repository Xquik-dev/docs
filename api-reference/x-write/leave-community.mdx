## Leave a community with context

Use this route after confirming the current community membership. Resolve the
numeric community ID and connected account independently. Save the community
name and approval reference before leaving.

Generate a dedicated idempotency key for this departure. Do not reuse the
earlier join key. Reuse the departure key only for an exact retry.

Community departure workflows often include:

- Leaving a completed event or campaign community.
- Applying a reviewed membership-cleanup request.
- Correcting membership from the wrong connected account.
- Recording the departure time in an account ledger.

Store the action ID and lifecycle state. Keep a failed departure separate from
a confirmed result. Query community members afterward only when independent
verification is required.

## Headers

<ParamField header="x-api-key" type="string" required>
  Your API key. Session cookie authentication is also supported. Generate a key from the [dashboard](https://xquik.com/dashboard).
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Unique key for this intended write. Reuse it only for an exact network replay.
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Must be `application/json`.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  The ID of the community to leave.
</ParamField>

## Body

<ParamField body="account" type="string" required>
  The connected X account to remove from the community. Must be a username you have connected to your Xquik account.
</ParamField>
