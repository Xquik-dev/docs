## Follow a verified profile

Use this route after resolving the intended profile. Prefer the numeric user
ID when your workflow already has it. Show the current username, profile name,
and follower context before approval.

Assign a unique idempotency key to the follow decision. Reuse it only for an
exact network replay. Store the target ID, acting account, action ID, and
lifecycle state.

Follow workflows can support:

- Following a reviewed partner or customer account.
- Applying an approved list of profiles to one account.
- Recording relationship changes in a CRM activity stream.
- Preventing duplicate follows across concurrent workers.

Do not use this route for follower collection. Use the followers endpoint to
retrieve profile rows. Use the following endpoint to inspect existing outbound
relationships.

## Verify a Follow Before Dependent Workflows

Store the target user ID and connected account ID. Record the action ID, request time, and idempotency key.

Poll the write status until it reaches a terminal state. A queued response never proves the account followed the profile.

After success, use follower check when current relationship proof is required. An already-followed result confirms convergence. Do not submit a second follow.

On failure, preserve the generic error and request ID. Retry the same target with the same idempotency key.

| Follow decision column | Source | Audit rule |
| --- | --- | --- |
| `acting_account` | Request `account` | Keep the connected account separate from the target profile. |
| `target_user_id` | Path `id` | Use the stable numeric target ID. |
| `target_username` | Review context | Store as a readable label, not the relationship key. |
| `approval_reference` | Workflow value | Prove who or what approved the follow. |
| `idempotency_key` | Request header | Reuse only for the identical follow request. |
| `write_action_id` | Response `id` | Poll and reconcile the durable follow action. |
| `status` | Response `status` | Keep queued, completed, and failed states distinct. |
| `terminal` | Response `terminal` | Report completion only when this value is `true`. |
| `safe_to_retry` | Response `safeToRetry` | Retry only when the lifecycle response permits it. |

| Follow outcome | Evidence | Next action |
| --- | --- | --- |
| Queued | `terminal: false` | Poll `statusUrl`; do not claim the relationship changed. |
| Completed | Terminal success | Store the completion time and optional relationship proof. |
| Already followed | Converged terminal result | Complete the job without a second follow request. |
| Failed and retryable | `safeToRetry: true` | Follow lifecycle guidance and preserve the original receipt. |
| Failed and final | Terminal failure | Store the error and stop automatic retries. |
