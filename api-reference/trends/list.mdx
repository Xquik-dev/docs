## Use the Top-Level Twitter Trends API

`GET /trends` is Xquik's top-level regional trends route.
It returns ranked topics with WOEID context and a `total` field.
The `/x/trends` alias returns `count` instead of `total`.
Use one route consistently throughout each client.

  ```python Python
  import json
  import requests

  region_woeid = 23424977
  requested_count = 10
  response = requests.get(
      "https://xquik.com/api/v1/trends",
      params={"woeid": region_woeid, "count": requested_count},
      headers={"x-api-key": "xq_your_api_key_here"},
  )
  data = response.json()
  returned_total = len(data["trends"])
  trend_rows = [
      {
          "trend_name": trend["name"],
          "rank": trend.get("rank"),
          "description": trend.get("description"),
          "search_query": trend.get("query", trend["name"]),
          "region_woeid": data["woeid"],
          "requested_count": requested_count,
          "returned_total": returned_total,

      for trend in data["trends"]

  for row in trend_rows:
  ```

  ```go Go
  package main

  import (
    "encoding/json"
    "log"
    "net/http"
    "os"
  )

  type Trend struct {
    Name        string  `json:"name"`
    Rank        *int    `json:"rank,omitempty"`
    Description *string `json:"description,omitempty"`
    Query       *string `json:"query,omitempty"`
  }

  type TrendsResponse struct {
    Trends []Trend `json:"trends"`
    Total  int     `json:"total"`
    Woeid  int     `json:"woeid"`
  }

  type TrendRow struct {
    TrendName      string  `json:"trend_name"`
    Rank           *int    `json:"rank"`
    Description    *string `json:"description"`
    SearchQuery    string  `json:"search_query"`
    RegionWoeid    int     `json:"region_woeid"`
    RequestedCount int     `json:"requested_count"`
    ReturnedTotal  int     `json:"returned_total"`
  }

  func main() {
    const requestedCount = 10
    req, err := http.NewRequest("GET", "https://xquik.com/api/v1/trends?woeid=23424977&count=10", nil)
    if err != nil {
      log.Fatal(err)
    }
    req.Header.Set("x-api-key", "xq_your_api_key_here")

    resp, err := http.DefaultClient.Do(req)
    if err != nil {
      log.Fatal(err)
    }
    defer resp.Body.Close()

    var data TrendsResponse
    if err := json.NewDecoder(resp.Body).Decode(&data); err != nil {
      log.Fatal(err)
    }

    returnedTotal := len(data.Trends)
    encoder := json.NewEncoder(os.Stdout)
    for _, trend := range data.Trends {
      searchQuery := trend.Name
      if trend.Query != nil {
        searchQuery = *trend.Query
      }
      if err := encoder.Encode(TrendRow{
        TrendName:      trend.Name,
        Rank:           trend.Rank,
        Description:    trend.Description,
        SearchQuery:    searchQuery,
        RegionWoeid:    data.Woeid,
        RequestedCount: requestedCount,
        ReturnedTotal:  returnedTotal,
      }); err != nil {
        log.Fatal(err)
      }
    }
  }
  ```

## Build a Regional Twitter Trending Monitor

Use `GET /trends` when a dashboard, alerting job, content queue, warehouse, or
agent needs ranked X topics for a supported WOEID region.

The Node.js, Python, and Go examples emit one JSON line per trend.
Store `trend_name`, `rank`, `description`, and `search_query`.
Also store `region_woeid`, `requested_count`, and `returned_total`.
Use `search_query` as the input for [Search Tweets](/api-reference/x/search-tweets).
That search can retrieve related tweets, hashtags, or brand mentions.
A Twitter API trends client should save each snapshot before starting that search.

Map `trends[].name` to `trend_name` and `trends[].query` to `search_query`.
Map `woeid` to `region_woeid` and request `count` to `requested_count`.
Derive `returned_total` from `trends.length`. The raw `total` field remains the
number of valid trends available before `count` slicing.

Poll one WOEID on a stable schedule. Compare ranks only within that region.
A Twitter API trending workflow creates history by storing those snapshots.
The route itself returns current trends, not a historical archive.
Keep missing optional fields unset. Preserve `tweetVolume` as null when returned.

| Regional trend column | Response source | Monitoring rule |
| --- | --- | --- |
| Trend name | `trends[].name` | Display the ranked topic or hashtag. |
| Search query | `trends[].query` | Pass this value to tweet search. |
| Rank | `trends[].rank` | Compare topic position across snapshots. |
| Description | `trends[].description` | Preserve the returned regional context. |
| Region | `woeid` | Keep the requested market with every row. |
| Available trends | `total` | Record the count before request slicing. |
| Returned trends | `trends.length` | Compare this count with the requested limit. |

## Headers

<ParamField header="x-api-key" type="string">
  Full account key. Sessions and OAuth also work.
</ParamField>

<ParamField header="Authorization" type="string">

## Query Parameters

<ParamField query="woeid" type="number">
  Region WOEID. See supported regions below. Omit it to use `1` for Worldwide.
</ParamField>

<ParamField query="count" type="number">
  Number of trends to return. Max `50`, default `30`.
</ParamField>

## Response

### 200 OK

<ResponseField name="trends" type="object[]">
  Array of trending topics. Map `name` to `trend_name` in integration rows.
  Map `query` to `search_query`.
  **Trend object fields:**
    <ResponseField name="name" type="string">Trend name or hashtag.</ResponseField>
    <ResponseField name="description" type="string">Short description. Omitted if unavailable.</ResponseField>

### 400 Invalid Input

```json
{ "error": "invalid_input" }
```
Unsupported or malformed `woeid`. Use one of the WOEIDs in the regions table. `count` is clamped between 1 and 50; nonnumeric values fall back to 30.

### 401 Unauthenticated

```json
{ "error": "unauthenticated" }
```
Missing or invalid API key. Check the `x-api-key` header value.

### 402 Payment Required

Account keys receive account payment options. Guest keys receive guest top-up.
Anonymous direct MPP calls receive a `WWW-Authenticate: Payment` challenge.
They also receive a guest wallet action. Confirm a payment option first.
No checkout starts automatically.

### 502 X API Unavailable

```json
{ "error": "x_api_unavailable" }
```
The read service is temporarily unavailable. Retry with exponential backoff.

### 429 Rate Limit Exceeded

```json
{ "error": "rate_limit_exceeded", "retryAfter": 60 }
```
Your tier rate limit was exceeded. Wait for the `Retry-After` header before retrying.

### 424 Dependency Failed

```json
{ "error": "x_api_unavailable" }
```
The opt-in normalized contract returns 424 when the read service fails.
Send `xquik-api-contract: 2026-04-29` to opt in. Default v1 returns 502.

## Twitter Trends API Questions

### How Do I Get Twitter Trends Programmatically?

Call `GET /trends` with a WOEID and result count.
Read each name, rank, query, description, public post count, and search URL.

### Can I Get Location-Based Trending Topics?

Yes. Use a supported WOEID for Worldwide, a country, or a listed region.
Keep that WOEID with every snapshot and rank comparison.

### Does The API Return Historical Twitter Trends?

No. Each request returns a current regional snapshot.
Create history by storing timestamped responses on a consistent schedule.

### How Do I Authenticate to the Twitter Trends API?

Send an Xquik API key or OAuth bearer token.
Guest keys and direct MPP credentials follow the header guidance above.

### Is the Twitter Trends API Free?

No. Each successful call uses the amount shown in the pricing callout.
Rate-limit responses include retry guidance and consume no successful result.

### Does This Replace X's Official API?

No. This page documents Xquik, an independent third-party service.
It does not document X's official trends endpoint.
