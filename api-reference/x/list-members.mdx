## Direct list member handoff

Use `GET /x/lists/{id}/members` when a CRM, warehouse, audience, enrichment, or
agent workflow needs one JSON page of accounts on a list. Use
[`list_member_extractor`](/api-reference/extractions/create) when you need a
saved extraction, estimated job, or CSV/JSON/XLSX file export.

Store `list_id`, `member_id`, `username`, `display_name`, profile metrics,
verification state, `has_next_page`, and `next_cursor`. Treat `next_cursor` as
opaque and pass it back as `cursor` only when `has_next_page` is true. Set
`pageSize` from 20 to 200 for direct calls. Zero affordable results return
`402 insufficient_credits`.

## Export a curated list roster

Use list members to understand which profiles a list owner selected. Preserve
the list ID on every row. Also preserve the page cursor and collection time.

Useful list-member columns include:

- User ID, username, and profile name.
- Biography, location, and verification state.
- Follower and following counts.
- List ID and collection timestamp.

Compare snapshots by user ID to find additions and removals. Do not compare
only usernames. Profile owners can rename their accounts.

List membership reflects curation, not audience interest. Use list followers
to retrieve profiles that follow the list. Use user followers for profiles
following a specific account.

For CRM imports, deduplicate by list ID and user ID. This allows the same
profile to appear correctly in several lists.

## Track list curation changes

Create complete snapshots at consistent intervals. Mark added user IDs as new
members. Mark missing IDs as removals only after a complete later snapshot.

Keep the list name and owner in your snapshot metadata. The endpoint path uses
the list ID, while reviewers often recognize the readable name.

Use member changes to review curation decisions. Do not describe them as
follower growth. A list owner controls membership.

Create one change row for each added or removed user ID. Include the earlier
and later snapshot times. Keep the current username only as a display label.

Send uncertain comparisons to review. Do not publish changes from incomplete
snapshots.

### 400 Invalid list ID

```json
{ "error": "invalid_list_id", "message": "List ID required" }
```
The list ID path parameter is empty.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.
```json
{ "error": "unauthenticated" }
```
Missing or invalid API key.

### 402 Payment required

Account keys get account options; guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 404 List not found

```json
{ "error": "not_found" }
```
The list could not be resolved. Check the list ID.

### 502 X API unavailable

```json
{ "error": "x_api_unavailable" }
```
The read service returned an error. Retry after a short delay.

### 429 Rate Limit Exceeded

```json
{ "error": "rate_limit_exceeded", "retryAfter": 60 }
```
Your tier rate limit was exceeded. Wait for the `Retry-After` header before retrying.

### 424 Dependency Failed

```json
{ "error": "x_api_unavailable" }
```
The normalized v1 response contract can return 424 when the read service is unavailable.
