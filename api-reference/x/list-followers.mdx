Use this Twitter List followers API to retrieve subscriber profiles for one
accessible X List. Export stable user IDs, usernames, bios, profile locations,
verification, follower counts, following counts, profile images, and cursors.

## Twitter List Followers Questions

### What Is a Twitter List Follower?

A List follower subscribes to one List. A List member is an account selected
by the List owner. An account follower follows one profile instead.

X says anyone can follow a public List. Only its owner can access a private
List. Read X's official [Lists guide](https://help.x.com/en/using-x/x-lists)
for current List visibility and follow behavior.

### How Do I Find Who Follows a Specific Twitter List?

Copy the numeric List ID from its X URL. Request the first page without a
cursor. Store every returned user row before requesting another page.

Continue only when `has_next_page` is true. Pass `next_cursor` unchanged as
the next `cursor`. X documents the same relationship in its official
[Get List followers](https://docs.x.com/x-api/lists/get-list-followers) guide.

### How Do I Export Twitter List Followers?

The direct endpoint returns normalized JSON pages. Convert each profile into
one row. Store the List ID, user ID, username, bio, metrics, and collection
time.

Use `list_follower_explorer` for a saved Twitter List follower export. The job
can produce CSV, JSON, or XLSX files without custom spreadsheet code.

### Which List Follower Attributes Can I Analyze?

Analyze stable user IDs, usernames, bios, profile-declared locations, account
creation dates, verification, and public profile counts. Compare automation,
protected-account, and availability fields only when the response includes
them.

These fields do not reveal age, gender, income, private identity, consent, or
audience sentiment. Do not convert a profile location into verified residence.

### Can This API Add, Remove, or Buy List Followers?

No. This read endpoint cannot follow a List or remove a List follower. It
cannot create Lists, manage List members, publish posts, or buy followers.

Use the [List Members endpoint](/api-reference/x/list-members) for the curated
profile roster. That endpoint also reads profiles. It does not edit the List.

## Direct List Follower Handoff

Use `GET /x/lists/{id}/followers` when a CRM, warehouse, audience, enrichment,
or agent workflow needs one JSON page of accounts that follow a list. Use
[`list_follower_explorer`](/api-reference/extractions/create) when you need a
saved extraction, estimated job, or CSV/JSON/XLSX file export.

Store `list_id`, `follower_id`, `username`, `display_name`, profile metrics,
verification state, `has_next_page`, and `next_cursor`. Treat `next_cursor` as
opaque and pass it back as `cursor` only when `has_next_page` is true. Direct
calls return the default paid page size and cost 1 credit per user returned.
Zero affordable results return `402 insufficient_credits`.

## Measure Twitter List Follower Profiles

Use list followers to retrieve profiles that chose to follow one list. Keep
the list ID with every profile. This distinguishes audience rows from curated
list members.

Save these fields for analysis:

- User ID, username, and profile name.
- Biography, location, and verification state.
- Follower and following counts.
- List ID, cursor, and collection time.

Compare list-follower snapshots by user ID. Record newly observed and missing
IDs separately. Avoid treating a changed username as audience growth.

Use list members when you need the list owner’s curated roster. Use account
followers when you need the audience of one profile. These relationship types
answer different questions.

For outreach review, keep source list context. Never infer consent or contact
permission from a public follow relationship.

## Track List Audience Changes

Create complete follower snapshots before calculating additions or removals.
Record the list ID, collection time, page count, and final row count.

Use follower user IDs as stable comparison keys. Keep usernames only as
readable labels. Mark interrupted or credit-limited collections as partial.

Audience differences describe observed list follows. They do not describe
changes to the List's curated member roster.

Report newly observed follower IDs separately from missing IDs. Keep both
snapshot completion states beside the comparison.

Use follower differences for audience analysis only. A public follow does not
grant outreach permission or prove interest in every list topic.

### 400 Invalid List ID

```json
{ "error": "invalid_list_id", "message": "List ID required" }
```
The list ID path parameter is empty.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.
```json
{ "error": "unauthenticated" }
```
Missing or invalid API key.

### 402 Payment Required

Account keys get account options; guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 404 List Not Found

```json
{ "error": "not_found" }
```
The list could not be resolved. Check the list ID.

### 502 X API Unavailable

```json
{ "error": "x_api_unavailable" }
```
The read service returned an error. Retry after a short delay.

### 429 Rate Limit Exceeded

```json
{ "error": "rate_limit_exceeded", "retryAfter": 60 }
```
Your tier rate limit was exceeded. Wait for the `Retry-After` header before retrying.

### 424 Dependency Failed

```json
{ "error": "x_api_unavailable" }
```
The normalized v1 response contract can return 424 when the read service is unavailable.
