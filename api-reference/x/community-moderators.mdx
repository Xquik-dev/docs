Export moderator profiles for one X community. Store user IDs for access
reviews, audience analysis, or community monitoring.

  const communityId = "1234567890";
  const response = await fetch(`https://xquik.com/api/v1/x/communities/${communityId}/moderators`, {

Use `GET /x/communities/{id}/moderators` for moderator audits, governance
review, trust and safety queues, or CRM enrichment. It creates one row per
community moderator. Store `community_id`, `moderator_id`, `username`,
`display_name`, `bio`, `follower_count`, `verified`, `profile_image_url`, and
`next_cursor`. Store `page_size` and `has_next_page` with the checkpoint when
you paginate moderator audits or saved review queues.

## Direct moderator handoff

Use the first page with no `cursor`, then pass `next_cursor` back as `cursor`
while `has_next_page` is true. Requested result counts are upper bounds, so use
`page_size` to record how many moderators were returned on the current page.

## Audit a community moderation team

Use this route when the role matters more than general membership. Every
returned profile represents a moderator visible for the selected community.
Keep the community ID and collection time with each profile.

Review moderator rows for:

- User ID, username, and profile name.
- Verification state and public biography.
- Follower counts and profile image.
- Cursor position and collection time.

Compare snapshots by user ID. A changed username does not represent a new
moderator. Flag added and removed IDs for review.

Do not combine moderator rows with the full member roster silently. Give each
export a clear role column. This prevents downstream tools from granting
moderator meaning to ordinary members.

## Review moderator coverage

Compare complete moderator snapshots by community ID and user ID. Record added
and removed IDs without guessing the reason.

Keep one row per visible moderator. Store the current username only as a
label. Use the numeric user ID for durable joins.

Escalate unexpected changes to a human reviewer. Do not trigger account
actions from a roster difference alone.

Keep review outcomes separate from the public profile snapshot. Record the
reviewer, decision time, and community ID in your own system.

Refresh a profile only when current biography or counts matter. Preserve the
original moderator observation.

### 400 Invalid community ID

```json
{ "error": "invalid_community_id" }
```
The community ID is empty or invalid.

### 401 Unauthenticated

Anonymous requests get `WWW-Authenticate: Bearer` and a guest wallet checkout action. This is not a Payment challenge.
```json
{ "error": "unauthenticated" }
```
Missing or invalid API key.

### 402 Payment required

Account keys get account options; guest keys get guest top-up only.
No checkout starts automatically. Confirm any payment action.

### 404 Community not found

```json
{ "error": "not_found" }
```
The community could not be resolved. Check the community ID.

### 502 X API unavailable

```json
{ "error": "x_api_unavailable" }
```
The read service returned an error. Retry after a short delay.

### 429 Rate Limit Exceeded

```json
{ "error": "rate_limit_exceeded", "retryAfter": 60 }
```
Your tier rate limit was exceeded. Wait for the `Retry-After` header before retrying.

### 424 Dependency Failed

```json
{ "error": "x_api_unavailable" }
```
The normalized v1 response contract can return 424 when the read service is unavailable.
