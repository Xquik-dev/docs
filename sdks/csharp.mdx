Use the C# SDK for typed .NET Standard 2.0+ access to Xquik from services, workers, console tools, and ASP.NET backends. It is useful when a .NET job needs to search tweets, scrape tweets to JSON Lines or CSV, export followers, monitor tweets, post tweets, upload media, send direct messages, or hand X API data to queues and internal reporting systems.

## Install

```bash
dotnet add package XTwitterScraper
```

## Authenticate

```bash
export X_TWITTER_SCRAPER_API_KEY="xq_YOUR_KEY_HERE"
```

`new XTwitterScraperClient()` reads `X_TWITTER_SCRAPER_API_KEY`, `X_TWITTER_SCRAPER_BEARER_TOKEN`, and `X_TWITTER_SCRAPER_BASE_URL`.

## Basic Example

```csharp
using XTwitterScraper;
using XTwitterScraper.Models.X.Tweets;

XTwitterScraperClient client = new();

TweetSearchParams parameters = new()
{
    Q = "from:elonmusk",
    Limit = 10,
};

var tweets = await client.X.Tweets.Search(parameters);
```

## Workflow: Search Tweets to JSON Lines

Use this workflow when a .NET worker, console job, or ASP.NET background service needs tweet search results in a durable handoff format for a queue, data lake, analyst CSV export, or CRM enrichment step.

`client.X.Tweets.Search` calls `GET /x/tweets/search`. Build a `TweetSearchParams` object with the same query parameters the REST API accepts: `Q`, `Limit`, `Cursor`, `SinceTime`, `UntilTime`, and `QueryType`.

```csharp
using System.IO;
using System.Text.Json;
using XTwitterScraper;
using XTwitterScraper.Models;
using XTwitterScraper.Models.X.Tweets;

XTwitterScraperClient client = new();

string? cursor = null;
using StreamWriter writer = File.CreateText("tweets.jsonl");

do
{
    PaginatedTweets page = await client.X.Tweets.Search(
        new TweetSearchParams
        {
            Q = "from:xquikcom webhook OR SDK",
            Limit = 100,
            Cursor = cursor,
            QueryType = QueryType.Latest,
        }
    );

    foreach (SearchTweet tweet in page.Tweets)
    {
        var row = new
        {
            id = tweet.ID,
            text = tweet.Text,
            author_username = tweet.Author?.Username,
            created_at = tweet.CreatedAt,
            like_count = tweet.LikeCount,
            reply_count = tweet.ReplyCount,
            retweet_count = tweet.RetweetCount,
            quote_count = tweet.QuoteCount,
            view_count = tweet.ViewCount,
        };

        await writer.WriteLineAsync(JsonSerializer.Serialize(row));
    }

    cursor = page.HasNextPage ? page.NextCursor : null;
} while (!string.IsNullOrEmpty(cursor));
```

### Request Mapping

| SDK property | REST query parameter | Use |
| --- | --- | --- |
| `Q` | `q` | X search query such as `from:username`, a keyword, or a boolean operator query. |
| `Limit` | `limit` | Maximum tweets to return for the page. |
| `Cursor` | `cursor` | Opaque cursor from `page.NextCursor` for the next page. |
| `SinceTime` | `sinceTime` | ISO 8601 lower bound for tweet creation time. |
| `UntilTime` | `untilTime` | ISO 8601 upper bound for tweet creation time. |
| `QueryType` | `queryType` | `QueryType.Latest` for chronological search or `QueryType.Top` for engagement-ranked search. |

### Returned Data & Handoff

`client.X.Tweets.Search` returns `PaginatedTweets`. Use `page.Tweets` for the tweet array, `page.HasNextPage` to decide whether another page exists, and `page.NextCursor` as the checkpoint for the next request.

Each `SearchTweet` includes typed properties such as `ID`, `Text`, `Author`, `CreatedAt`, `LikeCount`, `ReplyCount`, `RetweetCount`, `QuoteCount`, and `ViewCount` when available. Write `page.Tweets` as JSON Lines for queues and data lakes, transform the same rows into CSV for analysts, or write XLSX from the projected rows when account managers need a spreadsheet.

Tweet search costs 1 credit per tweet returned. If remaining credits cannot cover the requested page, the API can return fewer tweets than `Limit`; if 0 paid results are affordable, it returns `402 insufficient_credits`. The SDK retries connection errors, 408, 409, 429, and 5xx responses 2 times by default. For longer workers, set `MaxRetries` on the client and persist `NextCursor` after each page.

## Workflow: Post Image Tweets and DM Attachments

Use this workflow when a .NET worker needs to publish an image tweet, reply with an image, or send a direct message with an uploaded local file. `client.X.Tweets.Create` maps to `POST /x/tweets`; pass public image URLs through `Media`. For replies, set `ReplyToTweetID` to the parent tweet ID. `client.X.Media.Upload` maps to `POST /x/media`; use `media.MediaID` only for the one-item `MediaIds` handoff on `client.X.Dm.Send`.

```csharp
using System.IO;
using System.Text.Json;
using XTwitterScraper;
using XTwitterScraper.Models.X.Dm;
using XTwitterScraper.Models.X.Media;
using XTwitterScraper.Models.X.Tweets;

XTwitterScraperClient client = new();

TweetCreateResponse tweet = await client.X.Tweets.Create(
    new TweetCreateParams
    {
        Account = "@xquikcom",
        Text = "Shipping the weekly X API export.",
        Media = new[] { "https://static.example.com/reports/x-api-export.png" },
    }
);

TweetCreateResponse reply = await client.X.Tweets.Create(
    new TweetCreateParams
    {
        Account = "@xquikcom",
        Text = "Here is the chart behind the update.",
        Media = new[] { "https://static.example.com/reports/reply-chart.png" },
        ReplyToTweetID = tweet.TweetID,
    }
);

await using FileStream localFile = File.OpenRead("handoff.png");
MediaUploadResponse media = await client.X.Media.Upload(
    new MediaUploadParams
    {
        Account = "@xquikcom",
        File = localFile,
    }
);

DmSendResponse dm = await client.X.Dm.Send(
    "44196397",
    new DmSendParams
    {
        Account = "@xquikcom",
        Text = "Here is the requested asset.",
        MediaIds = new[] { media.MediaID },
    }
);

var handoff = new
{
    tweet_id = tweet.TweetID,
    reply_tweet_id = reply.TweetID,
    dm_message_id = dm.MessageID,
};

await Console.Out.WriteLineAsync(JsonSerializer.Serialize(handoff));
```

Store `tweet.TweetID` and `reply.TweetID` on the CMS, queue job, or agent state before scheduling follow-up work. Store `dm.MessageID` on the support ticket or CRM note. Each tweet or reply write costs 10 credits. Uploading media costs 10 credits, and sending the DM costs 10 credits. Do not pass uploaded `media.MediaID` values to `client.X.Tweets.Create`; that method uses `Media` with public image URLs.

## Error Handling

The C# SDK throws generated exception types for non-success responses and connection failures.

| Status | Exception |
| --- | --- |
| 400 | `XTwitterScraperBadRequestException` |
| 401 | `XTwitterScraperUnauthorizedException` |
| 403 | `XTwitterScraperForbiddenException` |
| 404 | `XTwitterScraperNotFoundException` |
| 422 | `XTwitterScraperUnprocessableEntityException` |
| 429 | `XTwitterScraperRateLimitException` |
| 5xx | `XTwitterScraper5xxException` |

Use the [error handling guide](/guides/error-handling) for response body fields and retry recommendations.

## Pagination

Paginated responses expose generated fields such as `HasNextPage`. Pass cursor parameters from the previous response when an endpoint supports cursor pagination.

```csharp
if (tweets.HasNextPage)
{
    await Console.Error.WriteLineAsync("More results are available");
}
```
