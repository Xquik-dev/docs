Use the CLI when a shell script, cron job, CI workflow, or operations runbook needs X API data without an application wrapper. It can search tweets, scrape tweets to JSON, export follower data, upload media, post tweets, post tweet replies, send direct messages, monitor tweets, and hand results to `jq`, Python, a warehouse loader, or a queue worker.

## Install

```bash
go install github.com/Xquik-dev/x-twitter-scraper-cli/cmd/x-twitter-scraper@latest
```

Make sure your Go bin directory is on `PATH`:

```bash
export PATH="$PATH:$(go env GOPATH)/bin"
```

## Authenticate

```bash
export X_TWITTER_SCRAPER_API_KEY="xq_YOUR_KEY_HERE"
```

You can also pass `--api-key` per command or use `X_TWITTER_SCRAPER_BEARER_TOKEN` for OAuth 2.1 access tokens.

## Basic Example

```bash
x-twitter-scraper x:tweets search \
  --q from:elonmusk \
  --limit 10 \
  --format json
```

Use `--help` at any level:

```bash
x-twitter-scraper x:tweets search --help
```

## Workflow: Search Tweets to JSON Lines

Use this workflow when an analyst, data engineer, or growth operator needs tweets from an X search query in a file that can be loaded into a warehouse, spreadsheet pipeline, CRM enrichment job, or queue.

The CLI command below calls `GET /x/tweets/search`. It maps the same REST API query parameters to flags: `--q`, `--limit`, `--cursor`, `--since-time`, `--until-time`, and `--query-type`.

```bash
x-twitter-scraper x:tweets search \
  --q "from:xquikcom webhook OR SDK" \
  --query-type Latest \
  --limit 100 \
  --format json > first-page.json
```

The response includes `.tweets[]`, `.has_next_page`, and `.next_cursor`. Each tweet can include `id`, `text`, `createdAt`, engagement counts, `author`, `media`, `quoted_tweet`, and `retweeted_tweet`, depending on what X returns for the result.

Write one JSON object per line for downstream jobs:

```bash
jq -c '.tweets[] | {
  id,
  text,
  author_username: (.author.username // ""),
  created_at: (.createdAt // ""),
  like_count: (.likeCount // 0),
  reply_count: (.replyCount // 0),
  retweet_count: (.retweetCount // 0),
  quote_count: (.quoteCount // 0),
  view_count: (.viewCount // 0)
}' first-page.json > tweets.jsonl
```

Save the cursor with the job checkpoint before requesting the next page:

```bash
cursor="$(jq -r '.next_cursor // empty' first-page.json)"

if [ -n "$cursor" ]; then
  x-twitter-scraper x:tweets search \
    --q "from:xquikcom webhook OR SDK" \
    --cursor "$cursor" \
    --limit 100 \
    --format json > next-page.json
fi
```

Tweet search costs 1 credit per tweet returned. If remaining credits cannot cover the requested page, the API can return fewer tweets than `--limit`; if 0 paid results are affordable, it returns `402 insufficient_credits`. Use `--format-error json` so batch jobs can branch on `status` and `code`, and retry `429` or temporary `5xx` responses with backoff.

For CSV or XLSX handoff, keep `tweets.jsonl` as the source of truth and convert it in your pipeline. For example, a Python step can load each JSON Lines row and write selected columns to CSV for analysts, or to XLSX for account management workflows.

## Workflow: Post Image Tweets, Replies, and DM Attachments

Use this workflow when an operator, support queue, or agent needs to publish an image-backed tweet, reply with an image, or send one media attachment in a DM from a connected X account.

Tweet and reply image posts use public media URLs directly on `x:tweets create`. Do not upload first when you already have public image URLs.

```bash
x-twitter-scraper x:tweets create \
  --account @xquikcom \
  --text "New export workflow is live." \
  --media https://example.com/export-preview.png \
  --format json > posted-tweet.json
```

To reply with media, add the parent tweet ID. The `--reply-to-tweet-id` flag maps to `reply_to_tweet_id`, and `--media` maps to the public URL array on `POST /x/tweets`.

```bash
x-twitter-scraper x:tweets create \
  --account @xquikcom \
  --text "Here is the requested screenshot." \
  --reply-to-tweet-id 1893704267862470862 \
  --media https://example.com/export-preview.png \
  --format json > posted-reply.json
```

The response returns `tweetId` and `success`. If the API returns `202 x_write_unconfirmed`, store `writeActionId` and poll `GET /x/write-actions/{id}` before sending another write. Each create-tweet call costs 10 credits.

Use `x:media upload` when you need an uploaded media ID for a DM attachment. The CLI upload command accepts a local file through `--file`; `--transform mediaId` extracts the upload response ID for scripts.

```bash
media_id="$(x-twitter-scraper x:media upload \
  --account @xquikcom \
  --file ./handoff.png \
  --transform mediaId \
  --raw-output)"

x-twitter-scraper x:dm send \
  --account @xquikcom \
  --user-id 44196397 \
  --text "Here is the asset." \
  --media-id "$media_id" \
  --format json > sent-dm.json
```

The `--media-id` flag maps to the REST `media_ids` body field. DMs accept exactly 1 uploaded media ID. Store `messageId` from the DM response on the support ticket, CRM record, queue job, or agent memory. Uploading media costs 10 credits, and sending the DM costs 10 credits.

Do not pass uploaded `mediaId` values to `x:tweets create`; that command uses `--media` with public image URLs.

## Useful Commands

| Job | CLI command | Returned data |
| --- | --- | --- |
| Search tweets or scrape tweets | `x-twitter-scraper x:tweets search` | Tweet objects, author objects, metrics, media, `has_next_page`, `next_cursor` |
| Fetch one tweet | `x-twitter-scraper x:tweets retrieve` | Full tweet text, author, metrics, media, quoted tweet, retweeted tweet |
| Get tweet replies | `x-twitter-scraper x:tweets get-replies` | Reply tweets plus cursor fields |
| Export followers | `x-twitter-scraper x:users retrieve-followers` | User profiles, follower counts, cursor fields |
| Post a tweet or reply | `x-twitter-scraper x:tweets create` | `tweetId` and `success`, or `writeActionId` when confirmation is pending |
| Upload media for a DM attachment | `x-twitter-scraper x:media upload` | `mediaId` for one-item DM `media_ids`, `mediaUrl` for tweet `media` URL handoff |
| Send a direct message | `x-twitter-scraper x:dm send` | `messageId` and `success` |

Use `--format json` for scripts, `--format yaml` for readable operations output, and `--transform` with GJSON syntax when you only need one field from the response.

## Error Handling

The CLI writes API errors to stderr and exits non-zero for failed requests. Use `--format-error json` when scripts need machine-readable errors.

```bash
x-twitter-scraper x:users retrieve-search \
  --q not-a-real-user \
  --format json \
  --format-error json
```

Retryable API responses follow the same semantics as the REST API. See [error handling](/guides/error-handling) and [rate limits](/guides/rate-limits).

## Pagination

Commands that call paginated endpoints include pagination fields in their JSON output. Keep the response body when your script needs to request the next page with endpoint cursor parameters.
