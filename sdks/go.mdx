Use the Go SDK when you want typed parameters, context-aware requests, generated response models, and Go-native error handling.

Use this page when you need a Go service to search tweets, scrape tweets to JSON, export follower or profile data, post tweets, upload media, send DMs, monitor tweets, or hand X data to another system through SDK calls.

## Install

```bash
go get github.com/Xquik-dev/x-twitter-scraper-go
```

## Authenticate

```bash
export X_TWITTER_SCRAPER_API_KEY="xq_YOUR_KEY_HERE"
```

```go
client := xtwitterscraper.NewClient(
	option.WithAPIKey(os.Getenv("X_TWITTER_SCRAPER_API_KEY")),
)
```

## Basic Example

```go
package main

import (
	"context"
	"fmt"

	"github.com/Xquik-dev/x-twitter-scraper-go"
	"github.com/Xquik-dev/x-twitter-scraper-go/option"
)

func main() {
	client := xtwitterscraper.NewClient(option.WithAPIKey("xq_YOUR_KEY_HERE"))

	tweets, err := client.X.Tweets.Search(context.TODO(), xtwitterscraper.XTweetSearchParams{
		Q:     "from:elonmusk",
		Limit: xtwitterscraper.Int(10),
	})
	if err != nil {
		panic(err)
	}

	fmt.Printf("%+v\n", tweets.HasNextPage)
}
```

## Workflow: Search Tweets to JSON Lines

This job is for backend workers that need searchable tweet data in a stable handoff format. It calls `GET /x/tweets/search` through `client.X.Tweets.Search`, requests the newest matching tweets, and writes each returned tweet as one JSON object per line.

```go
package main

import (
	"context"
	"encoding/json"
	"os"

	"github.com/Xquik-dev/x-twitter-scraper-go"
	"github.com/Xquik-dev/x-twitter-scraper-go/option"
)

func main() {
	client := xtwitterscraper.NewClient(
		option.WithAPIKey(os.Getenv("X_TWITTER_SCRAPER_API_KEY")),
	)

	encoder := json.NewEncoder(os.Stdout)
	cursor := ""

	for {
		params := xtwitterscraper.XTweetSearchParams{
			Q:         "from:xquikcom webhook OR SDK",
			Limit:     xtwitterscraper.Int(100),
			QueryType: xtwitterscraper.XTweetSearchParamsQueryTypeLatest,
		}
		if cursor != "" {
			params.Cursor = xtwitterscraper.String(cursor)
		}

		page, err := client.X.Tweets.Search(context.Background(), params)
		if err != nil {
			panic(err)
		}

		for _, tweet := range page.Tweets {
			if err := encoder.Encode(tweet); err != nil {
				panic(err)
			}
		}

		if !page.HasNextPage || page.NextCursor == "" {
			break
		}
		cursor = page.NextCursor
	}
}
```

The example builds an `XTweetSearchParams` request so the Go fields stay aligned with `GET /x/tweets/search`. The generated params map directly to the REST endpoint:

| Go field | REST query parameter | Use it for |
| --- | --- | --- |
| `Q` | `q` | Required X search query with keywords, handles, hashtags, or operators. |
| `Limit` | `limit` | Page size from 1 to 200. Remaining credits can lower the returned count. |
| `Cursor` | `cursor` | Opaque cursor from `NextCursor` for the next page. |
| `SinceTime` | `sinceTime` | ISO 8601 lower time bound. |
| `UntilTime` | `untilTime` | ISO 8601 upper time bound. |
| `QueryType` | `queryType` | `Latest` for chronological results or `Top` for engagement-ranked results. |

## Returned Data & Handoff

`client.X.Tweets.Search` returns `PaginatedTweets`:

| Go field | JSON field | Handoff value |
| --- | --- | --- |
| `Tweets` | `tweets` | Array of tweet records. Each tweet includes `ID`, `Text`, `Author`, `CreatedAt`, `LikeCount`, `ReplyCount`, `RetweetCount`, `QuoteCount`, `BookmarkCount`, `ViewCount`, and `IsNoteTweet` when available. |
| `HasNextPage` | `has_next_page` | Boolean that tells your worker whether another page exists. |
| `NextCursor` | `next_cursor` | Cursor to store with the job checkpoint and pass back as `Cursor`. |

Write `Tweets` as JSON Lines for queues and data lakes, transform the same records into CSV or XLSX for analysts, or pass `ID`, `Text`, `Author.Username`, `CreatedAt`, and engagement counts into your CRM or enrichment pipeline.

## Workflow: Post Image Tweets and DM Attachments

Use this workflow when a Go worker, queue consumer, or agent service needs to post an image-backed tweet, reply with an image, or send one uploaded media item in a DM.

Tweet and reply image posts use public image URLs directly on `client.X.Tweets.New`. Do not upload first when the image URL is already public.

```go
tweet, err := client.X.Tweets.New(context.Background(), xtwitterscraper.XTweetNewParams{
	Account: "@xquikcom",
	Text:    xtwitterscraper.String("New export workflow is live."),
	Media:   []string{"https://example.com/export-preview.png"},
})
if err != nil {
	panic(err)
}

fmt.Println(tweet.TweetID)
```

To post an image reply, add `ReplyToTweetID`:

```go
reply, err := client.X.Tweets.New(context.Background(), xtwitterscraper.XTweetNewParams{
	Account:        "@xquikcom",
	Text:           xtwitterscraper.String("Here is the requested screenshot."),
	ReplyToTweetID: xtwitterscraper.String("1893704267862470862"),
	Media:          []string{"https://example.com/export-preview.png"},
})
if err != nil {
	panic(err)
}

fmt.Println(reply.TweetID)
```

For DM attachments, upload the local file first and pass the returned `media.MediaID` as the only `MediaIDs` item:

```go
file, err := os.Open("./handoff.png")
if err != nil {
	panic(err)
}
defer file.Close()

media, err := client.X.Media.Upload(context.Background(), xtwitterscraper.XMediaUploadParams{
	Account: "@xquikcom",
	File:    file,
})
if err != nil {
	panic(err)
}

dm, err := client.X.Dm.Send(context.Background(), "44196397", xtwitterscraper.XDmSendParams{
	Account:  "@xquikcom",
	Text:     "Here is the asset.",
	MediaIDs: []string{media.MediaID},
})
if err != nil {
	panic(err)
}

fmt.Println(dm.MessageID)
```

`client.X.Tweets.New` returns `TweetID` for confirmed posts. `client.X.Media.Upload` returns `media.MediaID` for DM attachments, and `client.X.Dm.Send` returns `dm.MessageID` for support tickets, CRM records, queue jobs, or agent memory.

Each tweet or reply write costs 10 credits. Uploading media costs 10 credits, and sending the DM costs 10 credits. Do not pass uploaded `MediaID` values to `client.X.Tweets.New`; that method uses `Media` with public image URLs.

## Cost, Limits & Retries

Tweet search costs 1 credit per tweet returned. If remaining credits cannot cover the requested page, the API can return fewer tweets than `Limit`; if 0 paid results are affordable, it returns `402 insufficient_credits`. Read calls are rate-limited, and `429` responses include `Retry-After`.

Generated Go methods return `error` for connection failures and non-success responses. Retry connection errors, 408, 409, 429, and 5xx responses with backoff. Do not retry 400, 401, 403, 404, or 422 until the request, authentication, permission, or input issue is fixed.

## Error Handling

Generated Go methods return `error` for connection failures and non-success API responses. Check the concrete error type from the SDK when you need status-code specific handling, and use the [error handling guide](/guides/error-handling) for response semantics.

Common retryable cases are connection errors, 408, 409, 429, and 5xx responses.

## Pagination

List and search responses expose generated pagination fields such as `HasNextPage`. Pass cursor parameters from the previous response when the endpoint supports cursor pagination.

```go
if tweets.HasNextPage {
	fmt.Println("More results are available")
}
```
