## Durable Write Recovery

<Warning>
  Send one unique `Idempotency-Key` per intended write. Reuse it only for the
  same account, target, payload, and media.
</Warning>

1. Store `id`, `request.hash`, `billing`, and `statusUrl`.
2. Poll after `Retry-After` or `pollAfterMs` when `terminal` is `false`.
3. Trust `safeToRetry` and `nextAction` before any new write.

### 200 Terminal or 202 Active

Store terminal results. Poll active actions without creating another write.

| HTTP status | Required action |
| --- | --- |
| `200` | Store the terminal result and settled billing. |
| `202` | Poll the same action. Never submit another write. |
| `400` | Fix the named field. Use a new idempotency key. |
| `401` | Fix authentication. Do not retry unchanged. |
| `402` | Fund the account before another write. |
| `403` | Reconnect or resolve the account restriction. |
| `409` | Keep the original action. Use a new key for new input. |
| `422` | Fix the rejected request before retrying. |
| `429` | Wait for `Retry-After`. Preserve the same key. |
| `500` | Retry only when `safeToRetry` is `true`. |
| `503` | Poll while `terminal` is `false`. |

See [Get Write Action Status](/api-reference/x-write/get-write-action-status)
for every lifecycle field, terminal state, billing field, and retry rule.
