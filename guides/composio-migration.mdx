Migrate a Composio Twitter MCP workflow without losing tweet IDs, followers, replies, or cursors. Preserve webhooks and write confirmations too. Xquik uses one fixed MCP endpoint. It provides searchable Xquik REST routes through `explore`. Execute approved calls through `xquik`.

Composio remains an active product. Its current session MCP endpoints are not decommissioned. Choose Xquik for a fixed endpoint and managed X authorization. It also provides tweet reads, follower exports, monitors, and direct REST contracts.

## Verify the Current Composio Session Code

Composio's Python and TypeScript SDKs expose different creation signatures. Use version-specific code when documenting the system being replaced.

<CodeGroup>

```bash Python
python -m pip install "composio==0.15.0"
```

```bash TypeScript
npm install "@composio/core@0.14.1"
```

</CodeGroup>

### Python Session MCP

Python `composio==0.15.0` exposes `Composio.create()` with keyword arguments. It returns a session containing the MCP URL and headers.

```python
import os

from composio import Composio

composio_client = Composio(api_key=os.environ["COMPOSIO_API_KEY"])
session = composio_client.create(
    user_id=os.environ["USER_ID"],
    toolkits=["twitter"],
    auth_configs={
        "twitter": os.environ["COMPOSIO_TWITTER_AUTH_CONFIG_ID"],
    },
)

COMPOSIO_MCP_URL = session.mcp.url
COMPOSIO_MCP_HEADERS = session.mcp.headers
```

Do not pass `mcp=True` to this Python version. Its published signature does not accept that argument.

### TypeScript Session MCP

TypeScript `@composio/core==0.14.1` makes MCP an explicit typed option. Use the canonical `composio.sessions.create()` entry point.

```typescript
import { Composio } from "@composio/core";

const composio = new Composio({
  apiKey: process.env.COMPOSIO_API_KEY,
});

const session = await composio.sessions.create(process.env.USER_ID!, {
  toolkits: ["twitter"],
  authConfigs: {
    twitter: process.env.COMPOSIO_TWITTER_AUTH_CONFIG_ID!,
  },
  mcp: true,
});

const composioMcpUrl = session.mcp.url;
const composioMcpHeaders = session.mcp.headers;
```

Do not drop `session.mcp.headers`. Composio's hosted endpoint can require them.

## Configure the Xquik Twitter MCP Server

Add the fixed Xquik endpoint to each supported client.

<CodeGroup>

```bash Claude Code
claude mcp add --transport http xquik https://xquik.com/mcp
```

```bash Codex
codex mcp add xquik --url https://xquik.com/mcp
codex mcp login xquik
```

```json Cursor
{
  "mcpServers": {
    "xquik": {
      "url": "https://xquik.com/mcp"
    }
  }
}
```

</CodeGroup>

Complete Xquik login and consent through the client. Programmatic runtimes can use a supported API-key fallback. Store API keys in a secret manager.

<Warning>
  Affected Codex releases discard the RFC 9207 `iss` value before token exchange. Xquik already returns it. The error reads `Authorization server response missing required issuer: expected https://xquik.com`. Follow [Codex OAuth issuer validation error](/guides/troubleshooting#codex-oauth-issuer-validation-error) when issuer validation fails. Track [upstream issue #31573](https://github.com/openai/codex/issues/31573) for the fixed Codex release.
</Warning>

ChatGPT custom apps require OAuth. They cannot present custom Xquik API-key headers.

## Discover Routes Before Execution

The `explore` tool searches the authenticated Xquik catalog without executing a request. Ask it for route metadata before calling `xquik`.

```javascript
async () => {
  return spec.endpoints.filter((endpoint) =>
    endpoint.summary.toLowerCase().includes("followers"),
  );
}
```

Then call the selected route through `xquik.request()`.

```javascript
async () => {
  return xquik.request("/api/v1/x/tweets/search", {
    query: {
      q: '"model context protocol" lang:en -filter:retweets',
      queryType: "Latest",
      limit: 100,
    },
  });
}
```

Keep searches focused. Preserve the exact query beside every tweet page.

## Replace Provider-Specific Cursors

Never pass a Composio cursor into Xquik. Cursor formats belong to their source and request contract.

Start the Xquik shadow read at page one. Persist the first Xquik `next_cursor` only after storing its rows. Continue with the same route, query, ordering, limits, filters, and time window.

Xquik MCP list and search results use `has_more` and `next_cursor`. Pass `next_cursor` as `cursor` for tweets, profiles, followers, replies, timelines, communities, and lists. Use `after` for event replay and extraction pages.

Stop when `has_more` becomes false. Also stop on a missing or repeated cursor. Return the partial row count and a clear stop reason.

## Normalize Results Before Cutover

Composio and Xquik return different envelopes. Compare stable business rows, not raw provider payloads.

### Tweet Search Rows

Store request `q`, `query_type`, `since_time`, and `until_time`. Store each `tweet_id`, `text`, `author_id`, `author_username`, `created`, and `url`. Keep likes, reposts, replies, quotes, views, and bookmarks as separate metrics.

### Profile and Follower Rows

Store source `id` as `user_id`. Preserve `username`, `name`, `followers`, `following`, `verified`, and `profile_picture`. Keep follower and following rows in separate collections.

### Reply Rows

Store `tweet_id`, `conversation_id`, `in_reply_to_id`, `author_id`, `author_username`, `created`, `text`, and `url`. Keep nested replies separate from direct replies.

### Trend Rows

Store each trend `name`, `rank`, `query`, and `description`. Store response `count` and `woeid` with the batch.

### Monitor and Webhook Rows

Store `monitor_id`, `monitor_type`, and the webhook endpoint ID. Verify each webhook signature before parsing the body. Store `delivery_id` for delivery deduplication. Store `stream_event_id` for event deduplication.

### Stored Event Replay

Use `GET /api/v1/events` with `after`. Store `event_id`, `type`, `monitor_id`, `monitor_type`, `occurred_at`, `has_more`, and `next_cursor`.

Keep `tweet_rows`, `profile_rows`, `follower_rows`, `following_rows`, `reply_rows`, `trend_rows`, `webhook_event_rows`, and `event_replay_rows` separate.

## Migrate Reads Before Writes

Start with tweet search, profile lookup, followers, following, replies, and trends. Compare normalized rows during a shadow period.

Validate these invariants:

- Requested accounts and query windows match.
- Tweet and user IDs remain strings.
- Pagination reaches the expected stopping condition.
- Missing optional fields stay missing.
- Timestamps use one documented representation.
- Duplicate rows collapse by stable IDs.
- Error routes preserve status and safe categories.

Do not expect ranking order or engagement metrics to remain identical forever. Compare IDs, coverage, fields, and timestamps within the same test window.

## Cut Over Writes Safely

Do not run Composio and Xquik mutations in parallel. That can duplicate tweets, replies, likes, follows, DMs, or list changes.

<Steps>
  <Step title="Disable Composio Mutations">
    Keep read-only shadow checks active. Stop every old write path.
  </Step>
  <Step title="Require Explicit Approval">
    Show the action, account, text, recipients, and media before execution.
  </Step>
  <Step title="Execute One Xquik Write">
    Use the catalog-listed route or direct REST contract.
  </Step>
  <Step title="Store Durable IDs">
    Store `tweet_id`, `message_id`, or `write_action_id` immediately.
  </Step>
  <Step title="Confirm Terminal State">
    Poll pending write actions before retrying or showing success.
  </Step>
  <Step title="Enable the Remaining Writes">
    Migrate one mutation class at a time.
  </Step>
</Steps>

Never claim success from an accepted request alone. Confirm the documented terminal response.

## Preserve Media Workflows

For tweets and replies, pass public HTTPS image or MP4 URLs in `media`. Store `tweet_id` or `write_action_id` from the response.

For DMs, upload media first. Pass one returned `media_id` inside `media_ids`. Store `message_id`, `media_id`, account, and recipient. Leave `reply_to_message_id` unset unless the documented route requires it.

Do not copy Composio media identifiers into Xquik requests. Upload or reference media through the target contract.

Branch on the selected route's canonical statuses.

## Common Composio Twitter MCP Migration Questions

### Is Xquik a Composio Alternative for Twitter MCP?

Yes, when the workflow needs X-specific reads, exports, monitors, webhooks, and approved actions. Compare required routes instead of toolkit counts.

### Do I Need an X Developer Account for Xquik?

No X developer credentials are required. Complete Xquik authorization through its supported login or API-key flow.

### Can I Reuse a Composio MCP Session URL?

No. Configure `https://xquik.com/mcp` as a new server. Do not treat a Composio session URL as an Xquik credential.

### Can I Reuse Composio Pagination Cursors?

No. Restart at page one and store the new Xquik cursor after each committed page.

### Can Xquik Export Twitter Followers and Following?

Yes. Use the follower and following routes for pages. Use extraction jobs for durable file exports.

### How Do I Migrate Tweet Search Without Missing Posts?

Use the same query and time window during shadow reads. Compare stable tweet IDs and pagination checkpoints.

### How Do I Avoid Duplicate Tweets During Write Cutover?

Disable Composio mutations first. Execute one approved Xquik write and confirm its terminal result.

### Should I Compare Raw Composio and Xquik Responses?

No. Normalize stable tweet, profile, follower, reply, trend, and webhook rows first.
