Build a Mastra AI Twitter MCP agent through Xquik's remote MCP server. Search
tweets, inspect profiles, export followers, replay monitor events, and review
X actions. Preserve every tweet ID, profile ID, cursor, and job ID.

This Mastra AI tutorial provides typed examples. These Mastra AI TypeScript
examples cover agents, workflows, and tool calling. They also cover approval,
pagination, errors, and durable handoffs.

## Why Use the Mastra AI Agent Framework With a Twitter API?

The Mastra AI framework provides agents, model routing, tools, memory, and
workflows. Xquik supplies Twitter API operations through `explore` and
`xquik`. Together, they support typed tweet research and approved X actions.

Mastra is an open-source TypeScript framework for building AI applications.

Use each boundary for one responsibility.

| Boundary | Mastra control | Twitter agent benefit |
| --- | --- | --- |
| Remote MCP | `MCPClient` | Connect models to tweet, profile, follower, and monitor routes |
| Final response | Zod `structuredOutput` | Reject malformed tweet rows and pagination state |
| Per-call tools | `listToolsets()` | Isolate one tenant's Xquik credentials |
| X actions | `requireToolApproval` | Pause before the `xquik` execution tool runs |
| Error handling | `onToolError: "throw"` | Surface MCP failures instead of treating them as success |
| Cleanup | `disconnect()` | Close remote sessions and avoid leaked connections |

Choose Mastra when the surrounding service already uses TypeScript. Choose
direct REST for deterministic jobs without model decisions.

## Mastra Twitter API Prerequisites

- Node.js 22.13 or later
- An [Xquik API key](/x-api-quickstart) beginning with `xq_`
- An LLM provider key supported by Mastra
- Connect an X account for private reads or X write actions

Public X reads do not require X Developer credentials. Authenticate with
Xquik. Connect an X account only when the route requires it.

## Build a Mastra AI Agent Example for Tweet Search

Define the final handoff before creating the agent. Mastra validates the model
response against the Zod schema.

```typescript
import { writeFile } from "node:fs/promises";
import { Agent } from "@mastra/core/agent";
import { createStep, createWorkflow } from "@mastra/core/workflows";
import { MCPClient } from "@mastra/mcp";
import { z } from "zod";

const tweetRowSchema = z.object({
  tweet_id: z.string(),
  text: z.string(),
  author_username: z.string().nullable(),
  created: z.number().int().nullable(),
  url: z.string().url().nullable(),
});

const handoffSchema = z.object({
  query: z.string(),
  route_used: z.literal("GET /api/v1/x/tweets/search"),
  tweets: z.array(tweetRowSchema),
  has_more: z.boolean(),
  next_cursor: z.string().nullable(),
  pages_fetched: z.number().int().positive(),
  stop_reason: z.enum([
    "complete",
    "requested_limit",
    "cursor_stalled",
  ]),
});

const mcp = new MCPClient({
  servers: {
    xquik: {
      url: new URL("https://xquik.com/mcp"),
      requestInit: {
        headers: {
          "x-api-key": process.env.XQUIK_API_KEY!,
        },
      },
      onToolError: "throw",
    },
  },
  timeout: 60_000,
});

try {
  const agent = new Agent({
    id: "xquik-tweet-search-agent",
    name: "Xquik Tweet Search Agent",
    instructions: [
      "Use Xquik for Twitter API requests.",
      "Use GET /api/v1/x/tweets/search.",
      "Preserve exact tweet IDs, created timestamps, and cursors.",
      "Never invent missing tweet fields.",
      "Stop when the requested limit is reached.",
      "Stop if the server repeats a cursor.",
    ].join(" "),
    model: "openai/gpt-5",
    tools: await mcp.listTools(),
  });

  const searchStep = createStep({
    id: "search-twitter",
    inputSchema: z.object({ query: z.string().min(1) }),
    outputSchema: handoffSchema,
    execute: async ({ inputData }) => {
      const result = await agent.generate(
        `Search 50 latest tweets for: ${inputData.query}`,
        { structuredOutput: { schema: handoffSchema } },
      );

      return handoffSchema.parse(result.object);
    },
  });

  const tweetResearchWorkflow = createWorkflow({
    id: "xquik-tweet-research",
    inputSchema: z.object({ query: z.string().min(1) }),
    outputSchema: handoffSchema,
  })
    .then(searchStep)
    .commit();

  const run = await tweetResearchWorkflow.createRun();
  const workflowResult = await run.start({
    inputData: { query: "Mastra AI MCP" },
  });

  if (workflowResult.status !== "success") {
    throw new Error(`Tweet workflow ended with ${workflowResult.status}.`);
  }

  await writeFile(
    "xquik-mastra-handoff.json",
    JSON.stringify(workflowResult.result, null, 2),
    "utf8",
  );
} finally {
  await mcp.disconnect();
}
```

`MCPClient` namespaces tools from every configured server. `listTools()` suits
agent construction. `listToolsets()` groups tools by server for each call.

The client tries Streamable HTTP for URL servers. It can fall back to SSE when
the remote server requires it.

The MCP runtime returns normalized snake_case fields through
`xquik.request()`. It normalizes `createdAt` to the Unix-second field
`created`. Keep the Zod schema aligned with that contract.

## Run a Mastra AI Workflow for Tweet Research

The example creates one typed Mastra AI workflow. Its `inputSchema` accepts a
query. Its `outputSchema` requires the final tweet handoff.

The `inputSchema: z.object(...)` declaration validates every query. An
`outputSchema: z.object(...)` declaration can define a smaller response. This
workflow reuses `handoffSchema` and avoids duplicate contracts.

The `import { z } from "zod"` statement provides both workflow schemas.

Mastra core workflows chain steps with `.then()` and finish with `.commit()`.
`createRun()` creates isolated execution state. `start()` validates the initial
`inputData` before running the search step.

This pattern keeps model output behind Zod validation. A registered agent can
also run the workflow through a Mastra instance. Add human-in-the-loop approval
before any workflow step that writes to X.

Mastra AI workflows should preserve cursors between runs. Store the successful
`result` outside the model transcript. Tweet search is not a real-time event
stream. Use [monitors](/api-reference/monitors/create) for stored events.

When running Mastra in production, store each successful handoff immediately.

## Search Tweets With Precise Operators

Send the search route a focused `q`. Keep the exact query in the handoff.

| Search intent | Example `q` |
| --- | --- |
| Latest framework posts | `"Mastra" MCP` |
| One account's timeline | `from:mastra_ai since:2026-07-01 until:2026-08-01` |
| Popular TypeScript posts | `"Twitter API" TypeScript lang:en min_faves:25` |
| Questions without reposts | `"tweet search agent" ? -filter:retweets` |
| Exact tweet | A numeric Tweet ID or X status URL |

Use `queryType=Latest` for chronological monitoring. Use `Top` for
engagement-ranked research. See the [tweet search API
contract](/api-reference/x/search-tweets).

Pass `next_cursor` back unchanged. Never rebuild a cursor. Stop when
`has_more` becomes false. Also stop when a cursor repeats.

Deduplicate resumed results by `tweet_id`. Keep the original `q` beside every
page checkpoint.

## Require Approval for Twitter Actions

Xquik intentionally exposes one `xquik` execution tool. That tool can run
reads and writes allowed by the API key.

Tool-name checks cannot distinguish routes inside `xquik`. Require approval
for every `xquik` execution when the agent holds write access.

```typescript
const approvedMcp = new MCPClient({
  servers: {
    xquik: {
      url: new URL("https://xquik.com/mcp"),
      requestInit: {
        headers: { "x-api-key": process.env.XQUIK_API_KEY! },
      },
      requireToolApproval: ({ toolName }) => toolName === "xquik",
      onToolError: "throw",
    },
  },
});
```

The generated `xquik` tool pauses before execution. Your interface must show
the route, method, arguments, and selected X account.

Approve a suspended non-streaming run with
`agent.approveToolCallGenerate()`. Decline it with
`agent.declineToolCallGenerate()`. Pass the returned `runId` and suspended
`toolCallId`.

Never treat MCP annotations as an authorization boundary. The MCP
specification defines them as hints. Mastra exposes them for trusted-server
approval policies.

For public research, a guest `paid_reads` key provides a hard read-only
boundary. It exposes only eligible GET routes. See [guest
wallets](/guides/guest-wallets) for its exact scope.

## Expose Discovery Without Execution

Mastra receives namespaced tools from `listTools()`. Filter the returned map
when an agent should only inspect endpoint schemas.

```typescript
const tools = await mcp.listTools();
const discoveryTools = Object.fromEntries(
  Object.entries(tools).filter(([name]) => name.endsWith("_explore")),
);

const discoveryAgent = new Agent({
  id: "xquik-route-discovery-agent",
  name: "Xquik Route Discovery Agent",
  instructions: "Inspect Twitter API routes. Never execute an operation.",
  model: "openai/gpt-5",
  tools: discoveryTools,
});
```

This agent cannot execute Twitter API operations. Adding `xquik` enables every
operation authorized by the key.

Use `explore` before an unfamiliar operation. It returns the route, method,
parameters, and response fields. It does not call X.

## Use a Mastra AI MCP Client for Each User

Create one client after resolving the tenant identity. Never share one API key
across unrelated tenants.

```typescript
import { Agent } from "@mastra/core/agent";
import { MCPClient } from "@mastra/mcp";

async function runTenantRequest(prompt: string, userApiKey: string) {
  const tenantMcp = new MCPClient({
    id: crypto.randomUUID(),
    servers: {
      xquik: {
        url: new URL("https://xquik.com/mcp"),
        requestInit: {
          headers: { "x-api-key": userApiKey },
        },
        requireToolApproval: true,
        onToolError: "throw",
      },
    },
  });

  const agent = new Agent({
    id: "tenant-twitter-agent",
    name: "Tenant Twitter Agent",
    instructions: "Preserve tweet IDs, profile IDs, cursors, and job IDs.",
    model: "openai/gpt-5",
  });

  try {
    return await agent.generate(prompt, {
      toolsets: await tenantMcp.listToolsets(),
    });
  } finally {
    await tenantMcp.disconnect();
  }
}
```

Keep API keys outside prompts, memory, traces, and saved handoffs. Resolve each
key from your existing secret manager.

Mastra caches identical client configurations. Supply a unique `id` when
separate clients use otherwise identical settings.

## Forward Dynamic Headers Safely

Use custom `fetch` when headers depend on request context. Resolve the secret
before the remote request.

```typescript
const mcp = new MCPClient({
  servers: {
    xquik: {
      url: new URL("https://xquik.com/mcp"),
      fetch: async (url, init) => {
        const headers = new Headers(init?.headers);
        headers.set("x-api-key", await secretStore.getXquikKey());
        return fetch(url, { ...init, headers });
      },
      onToolError: "throw",
    },
  },
});
```

The `secretStore` object represents your existing secret manager. Never send
its returned key to the model.

Keep `forwardInstructions` disabled unless you trust the MCP server. Enabling
it injects remote server instructions into the agent's system prompt.

## Handle Twitter API Errors and Rate Limits

The tweet search contract documents these responses. Keep their meanings
separate.

| Status | Meaning | Agent action |
| --- | --- | --- |
| `400` | The search query is missing or invalid | Fix `q`; do not retry unchanged |
| `401` | Guest authentication cannot complete this request | Provide an Xquik key or connect X |
| `402` | The account lacks credits | Stop and request account action |
| `424` | The upstream X dependency failed | Retry with bounded backoff |
| `429` | The Twitter API rate limit applies | Wait for reset guidance, then resume the cursor |
| `502` | The X dependency returned an invalid response | Retry later without changing IDs |

Keep Mastra's default `onToolError: "throw"` behavior. The explicit setting
documents that decision. It surfaces MCP `isError` results as failed tool
calls.

Do not restart pagination after `429`. Preserve `next_cursor` and completed
tweet IDs. Deduplicate by `tweet_id` after recovery.

POST and DELETE routes document different statuses. Read each route before
building retry logic. See [error handling](/guides/error-handling).

## Choose Mastra MCP or Direct REST

| Requirement | Mastra with MCP | Direct REST API |
| --- | --- | --- |
| Natural-language tweet research | Strong fit | Write query logic yourself |
| TypeScript agent workflows | Native fit | Add an orchestrator |
| Scheduled follower export | Extra model step | Strong fit |
| Human-approved tweet posting | Built-in approval suspension | Build approval state yourself |
| Predictable latency and cost | Less predictable | More predictable |
| Typed final handoff | Zod `structuredOutput` | TypeScript SDK schema |

Use MCP when the model chooses among related Twitter operations. Use REST for
fixed routes, scheduled exports, or latency-sensitive services.

A JavaScript Twitter scraper library usually couples results to page markup.
Xquik returns documented tweet, profile, follower, cursor, and job contracts.
Choose the contract that matches your production workflow.

## Mastra AI Twitter MCP Questions

### Where Is the Mastra AI Documentation?

Use Mastra's official agent, workflow, and MCP guides. This guide adds Xquik's
tweet, profile, follower, monitor, and write contracts.

### Which Mastra AI Examples Does This Tutorial Include?

It covers installation, MCP discovery, tweet search, workflows, approvals, and
handoffs. It also covers pagination, rate limits, and tenant isolation.

### How Does the Mastra AI SDK Handle MCP?

`@mastra/mcp` supplies `MCPClient`. `@mastra/core` supplies agents and
workflows. Zod validates workflow inputs, outputs, and final agent responses.

### What Is a Mastra AI MCP Client?

It connects Mastra AI agents to remote MCP servers. Xquik exposes tweet,
profile, follower, monitor, extraction, webhook, and write operations.

### How Does a Mastra AI MCP Server Connection Work?

`MCPClient` connects through Streamable HTTP. It namespaces remote tools by
server. Xquik authenticates every execution with the `x-api-key` header.

### Can Mastra AI Agents Run Workflows?

Yes. Mastra AI workflows can call an agent inside a typed step. Validate every
step output before passing it forward.

### Does Mastra Support Remote MCP Servers?

Yes. `MCPClient` connects to URL-based Streamable HTTP servers. Xquik exposes
`explore` and `xquik` at `https://xquik.com/mcp`.

### How Do I Connect Mastra to a Twitter API?

Create `MCPClient` with the Xquik MCP URL. Send your Xquik API key through the
`x-api-key` header. Pass `listTools()` into `Agent.tools`.

### How Do I Search Tweets With TypeScript?

Ask the agent to call `GET /api/v1/x/tweets/search`. Supply `q`, `queryType`,
and a limit. Preserve `tweet_id`, `created`, and `next_cursor`.

### Can a Mastra Agent Export Twitter Followers?

Yes. Use the [followers API](/api-reference/x/followers) for paginated profile
rows. Use an extraction job for larger CSV, JSON, or XLSX exports.

### Can Mastra Monitor Tweets Without Repeated Searches?

Yes. Create an account or keyword monitor. Replay stored events by cursor.
Connect a webhook when the receiver can verify signatures.

### Can Mastra Post Tweets and Replies?

Yes. Connect an X account before posting. Require approval for every `xquik`
execution. Validate the account, text, reply ID, and media before approval.

See [create tweet](/api-reference/x-write/create-tweet) for the exact contract.

### How Should a Mastra Agent Handle Twitter Rate Limits?

Treat `429` separately from dependency failures. Save the current cursor and
completed tweet IDs. Resume after the reset guidance.

### Does MCP Tool Filtering Make Xquik Read-Only?

Only when the agent receives `explore` without `xquik`. The `xquik` tool can
run every operation authorized by the key.

### Why Does MCPClient Need `disconnect()`?

The client owns remote connections and optional local child processes.
Disconnect it in `finally`. Repeated disconnect calls remain safe.

### Mastra or LangChain for a Twitter Agent?

Choose Mastra for TypeScript-first agents and workflows. Choose LangChain for
its broad Python ecosystem or LangGraph orchestration. Xquik supports both.

### Mastra MCP or a JavaScript Twitter Scraper Library?

Choose Mastra MCP for model-selected operations and typed handoffs. Choose a
scraper library only when page-markup coupling fits your workflow.

### Should I Forward MCP Server Instructions to Mastra?

Keep forwarding disabled by default. Enable it only for trusted servers.
Remote instructions become part of the agent's system prompt.
