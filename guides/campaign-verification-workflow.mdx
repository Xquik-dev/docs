## Twitter Giveaway Automation Questions

### What Makes the Best Twitter Giveaway Picker?

The best Twitter giveaway picker records the complete draw request and proof.
It should store the source Tweet ID or URL. Keep winner count, backup count,
and the unique-author rule. Add participation filters, inspected entries,
selected winners, status, and draw ID. Stable user IDs matter more than
display names.

Use Xquik as a Twitter giveaway tool with reviewable Draws exports. Use the
dashboard when an operator should inspect the request first. Test retweet,
follow, keyword, hashtag, and mention filters when published. Test language,
account-age, follower-count, and uniqueness filters when published. Never add
an unstated eligibility rule after entry collection.

### How Do I Automate a Twitter Giveaway With an API?

Start with one source Tweet ID or `tweetUrl`. Define `winnerCount`, optional
backup winners, and every eligibility rule before creating the draw. Store that
request with the campaign record.

Call `POST /api/v1/draws` once. Keep the returned draw ID. Do not create another
draw because a client loses its local response. Query the draw history before
repeating an uncertain request.

Poll the stored draw to its terminal state. Export inspected entries and
selected winners. Keep the source Tweet ID, draw ID, and participant user IDs.
Add filters, timestamps, and verification states. Publish the public result URL
when campaigns need participant transparency. Keep API keys and private review
notes outside that record.

### Automate Twitter Giveaway

Write the campaign rules before collecting entries. Identify the source tweet,
entry window, winner count, backup count, and unique-author requirement. Add
published follow, retweet, keyword, hashtag, and mention rules. Then add any
published language, account-age, or follower threshold. Use only rules shown
to participants.

Create one draw and save its ID immediately. Treat an unknown create response
as an investigation, not permission to create another draw. Poll status, then
export `type=entries` and `type=winners`. Keep stable user IDs, not display
names, as participant keys. Store the request, status, filters, row counts,
and timestamps. Keep the result URL with the campaign audit.

### Tweet Draw Tool

A reliable tweet draw tool preserves more than winner names. It stores the
source Tweet ID and configured filters. It also keeps inspected participant
IDs, selected winners, backups, status, and draw ID. Export those rows for
later review.

Handle uncertain requests carefully. Search draw history before repeating a
create call. Match the source tweet and campaign time. Retry participant reads with
the same tweet, filter, and cursor. Save each page before advancing. Stop on
`402 insufficient_credits`, then fund or narrow the campaign. Never silently
change eligibility rules during a retry.

### Twitter Giveaway Picker API

A Twitter giveaway picker API should make eligibility testable. Supply one
source Tweet ID or URL. Add winner count, optional backup count, and published
filters. Xquik can evaluate documented follow, retweet, keyword, hashtag, and
mention conditions. It also supports documented language, account-age,
follower-count, and unique-author conditions.

After completion, export inspected entries and winners. Reconcile the exported
user IDs with stored requests and result counts. Keep draw ID, source Tweet ID,
filters, timestamps, status, winners, and backups. Add the public result URL
when used. Avoid pickers that return only display names. Hidden applied rules
cannot support a later eligibility review.

### How Do I Prove Giveaway Winners Were Eligible?

Export `type=entries` for inspected participants and `type=winners` for selected
winners. Keep the draw ID, source Tweet ID, user IDs, filters, timestamps, and
verification states.

Share the public result URL when participants need proof.
Keep API keys and private notes out of that public record.

## Programmatic Twitter Giveaway Draw Checklist

Use one source giveaway tweet for entry collection. Store its Tweet URL and
numeric Tweet ID. Define every participation condition before entries close.
Keep the closing time, winner count, and backup count with the draw request.

A Twitter contest should separate collection from winner selection. First,
collect replies, retweets, quotes, or followers. Then apply published filters.
Finally, select randomly from the eligible user IDs. This order makes the
picker workflow reviewable after the campaign ends.

Do not draw a random Twitter account from an unchecked follower snapshot.
Exclude spam accounts or inactive accounts only through published filters.
Useful filters include account age, follower count, language, and unique
authors. Never invent subjective filters after selecting the winner randomly.

Record the selected Twitter giveaway winner and every backup. Keep their stable
user IDs, applied filters, timestamps, and draw ID. Store whether each winner
was selected randomly from the verified entry set. Retain the giveaway post
and public result URL when participants need transparent evidence.

More engagement never weakens the proof requirements. Treat engagement
content as campaign context, never eligibility proof. A comment
picker can select replies, but it cannot prove follows or retweets. Run the
matching Twitter API checks before finalizing winners.

## Frequently Asked Questions

### How Does the Twitter Giveaway Picker Work?

The Twitter giveaway picker reads one source Tweet URL. It inspects replies and
the requested participation conditions. Optional checks cover retweets,
follows, keywords, hashtags, mentions, language, and account thresholds. The
draw selects winners from the remaining stable user IDs.

### How Does a Twitter Comment Picker Work?

A Twitter comment picker treats direct replies as potential entries.
Use [Get Tweet Replies](/api-reference/x/tweet-replies) to inspect reply text
and stable user IDs. A random comment picker can randomly select winners from
eligible reply authors. It cannot prove follows or retweets without matching
API checks. The current Draws contract does not accept likes as an eligibility
rule. Store each reply ID, author ID, text, timestamp, and cursor. Remove
duplicate authors before creating the draw. Apply only published keywords,
hashtags, mentions, language, and account thresholds.

### How Does a Twitter Retweet Picker Verify Entries?

A Twitter retweet picker reads stable user IDs from the retweeter list.
Use [Get Retweeters](/api-reference/x/retweeters) to page every available row.
Set `mustRetweet` only when the published rules require a repost. A Twitter
hashtag giveaway picker also checks reply text for each required hashtag. Use
a specific hashtag only when the published rules required it. Store each
retweeter user ID, page cursor, Tweet ID, and checked timestamp. Do not trust a
displayed repost count as participant proof. Page until `has_next_page` is
`false` before creating the final entry set.

### How Does a Twitter Random Giveaway Picker Choose Winners?

A Twitter random giveaway picker applies filters before random selection.
Set the number of winners and backup count in one
[Create Draw](/api-reference/draws/create) request. The draw can randomly pick
eligible stable user IDs after every published check. A Twitter giveaway
winner picker should store the entry count and draw ID. Keep every winner,
backup, and applied filter. Never randomly pick from an unchecked follower or
reply list. Store the original request before the draw runs. Export inspected
entries and winners after completion. Keep stable user IDs, positions, backup
flags, timestamps, and the public result URL.

### What Should I Publish With the Winner?

Publish the winner handle, giveaway tweet, and result URL when appropriate.
Keep the draw ID and verified user ID in your private audit. Never publish API
keys, internal notes, or unneeded participant details.

## Follow Check

Use this for one participant at a time. Store the participant handle, target
handle, response, and timestamp with the campaign record.

```bash
curl "https://xquik.com/api/v1/x/followers/check?source=participant_handle&target=username" \
  -H "x-api-key: xq_YOUR_KEY_HERE" | jq
```

## Giveaway Draw

Automate a Twitter giveaway draw with the Draws API. Use draws when the workflow should select winners from replies and optional
eligibility filters. Draws can require retweets, a follow target, hashtags,
keywords, mentions, language, account age, follower count, and unique authors.

```bash
curl -X POST https://xquik.com/api/v1/draws \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Content-Type: application/json" \
  -d '{
    "tweetUrl": "https://x.com/example_user/status/1893704267862470862",
    "winnerCount": 3,
    "backupCount": 2,
    "uniqueAuthorsOnly": true,
    "mustRetweet": true,
    "mustFollowUsername": "username",
    "requiredKeywords": ["entered"]
  }' | jq
```

Export participant rows with `type=entries` and selected winners with
`type=winners`.

```bash
curl "https://xquik.com/api/v1/draws/f4bd00a2-7b4e-4e59-8e1b-72e2c9f12345/export?format=csv&type=entries" \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -o campaign-entries.csv
```
