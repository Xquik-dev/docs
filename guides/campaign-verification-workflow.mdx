## Twitter Giveaway Automation Questions

### How Do I Automate a Twitter Giveaway With an API?

Start with one source Tweet ID or `tweetUrl`. Define `winnerCount`, optional
backup winners, and every eligibility rule before creating the draw. Store that
request with the campaign record.

Call `POST /api/v1/draws` once. Keep the returned draw ID. Do not create another
draw because a client loses its local response. Query the draw history before
repeating an uncertain request.

### What Makes a Reliable Twitter Giveaway Picker API?

A reliable picker records its source tweet, filters, entries, winners, and
execution result. It uses stable user IDs instead of display names. It also
exports inspected entries for later review.

Xquik draws can filter replies by retweet status, followed account, keywords,
hashtags, mentions, language, account age, follower count, and unique author.
Choose only rules stated in the published campaign.

### What Is the Best Tool for a Programmatic Twitter Giveaway Draw?

Choose a tool that exposes the full draw contract. Test entry collection,
eligibility filters, winner count, backup count, exports, errors, and public
result verification. Avoid tools that return only names without evidence.

Use the Xquik Draws API when code must create the draw and retain audit rows.
Use the dashboard when an operator should review the request interactively.
Both workflows should preserve the same campaign rules.

### How Should a Tweet Draw Tool Handle Retries?

Treat an unknown create result as an investigation. Search existing draw
history for the source tweet and campaign time. Reuse the existing draw when it
matches the intended request.

Retry participant reads with the same tweet, filter, and cursor. Store each page
before advancing. Stop on `402 insufficient_credits`, then fund or narrow the
campaign before resuming.

### How Do I Prove Giveaway Winners Were Eligible?

Export `type=entries` for inspected participants and `type=winners` for selected
winners. Keep the draw ID, source Tweet ID, user IDs, filters, timestamps, and
verification states.

Publish the public result URL when the campaign needs participant transparency.
Keep private API keys and internal review notes outside that public record.

## Follow Check

Use this for one participant at a time. Store the participant handle, target
handle, response, and timestamp with the campaign record.

```bash
curl "https://xquik.com/api/v1/x/followers/check?source=participant_handle&target=username" \
  -H "x-api-key: xq_YOUR_KEY_HERE" | jq
```

## Giveaway Draw

Automate a Twitter giveaway draw with the Draws API. Use draws when the workflow should select winners from replies and optional
eligibility filters. Draws can require retweets, a follow target, hashtags,
keywords, mentions, language, account age, follower count, and unique authors.

```bash
curl -X POST https://xquik.com/api/v1/draws \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -H "Content-Type: application/json" \
  -d '{
    "tweetUrl": "https://x.com/example_user/status/1893704267862470862",
    "winnerCount": 3,
    "backupCount": 2,
    "uniqueAuthorsOnly": true,
    "mustRetweet": true,
    "mustFollowUsername": "username",
    "requiredKeywords": ["entered"]
  }' | jq
```

Export participant rows with `type=entries` and selected winners with
`type=winners`.

```bash
curl "https://xquik.com/api/v1/draws/f4bd00a2-7b4e-4e59-8e1b-72e2c9f12345/export?format=csv&type=entries" \
  -H "x-api-key: xq_YOUR_KEY_HERE" \
  -o campaign-entries.csv
```

## Audit Row

Store one row per checked participant or draw entry. Do not rely on display
names as keys.

```json
{
  "campaign_id": "spring-launch-2026",
  "x_user_id": "9876543210",
  "username": "participant_handle",
  "tweet_id": "1893704267862470862",
  "proof_endpoint": "GET /api/v1/x/followers/check",
  "proof_cursor": null,
  "verification_state": "matched",
  "checked_at": "2026-05-24T19:30:00.000Z"
}
```
