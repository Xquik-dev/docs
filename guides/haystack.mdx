Haystack is an open source framework for Python AI applications. Use [`xquik-haystack`](https://github.com/Xquik-dev/xquik-haystack) for fresh X context in Haystack. This Haystack AI framework converts public tweets into typed Haystack `Document` objects. Each document includes tweet text, author fields, timestamps, metrics, and citation URLs.

This Haystack AI API integration supports RAG pipelines and agent workflows. It supplies cited tweets to large language models (LLMs) without granting write access. You can follow this guide when building AI applications with Haystack and current tweets.

The integration provides two read-only components:

<CardGroup cols={2}>
  <Card title="Search Public Tweets" icon="search">
    `XquikTweetSearch` searches keywords, hashtags, accounts, conversations, and
    exact phrases.
  </Card>
  <Card title="Fetch User Timelines" icon="user">
    `XquikUserTweetsFetcher` retrieves one public account's tweets and optional
    replies.
  </Card>
  <Card title="Preserve Citations" icon="link">

  </Card>
  <Card title="Continue Every Page" icon="list-tree">
    Both components return `has_more` and an opaque `next_cursor`.
  </Card>
</CardGroup>

Use these building blocks for search, timelines, monitoring research, and retrieval-augmented generation. They can retrieve relevant tweets for Haystack AI agents and Haystack AI RAG pipelines. Use the [followers API](/api-reference/x/followers) for follower exports. Use the [write API](/api-reference/x-write/create-tweet) for approved publishing. The Haystack integration does not expose those actions.

## Install Haystack and Xquik

Use Python 3.10 or newer. Pin both packages for repeatable pipeline builds.

```bash
python -m pip install "xquik-haystack==0.1.3" "haystack-ai==3.0.0"
```

Run `pip install` inside the AI application's virtual environment. Release `0.1.3` is published on PyPI. Haystack `3.0.0` uses one `Pipeline` class for synchronous and asynchronous runs.

Create an [Xquik API key](/x-api-quickstart), then export it locally.

```bash
export XQUIK_API_KEY="xq_..."
```

Never embed production keys in pipeline YAML, notebooks, or source control. Load the environment variable through a Haystack `Secret` object.

## Search Twitter Tweets in Python

`XquikTweetSearch` calls the `GET /x/tweets/search` search endpoint. It accepts standard X search syntax and structured filters. Use it for each Twitter API keyword search or exact phrase query.

```python
from haystack import Pipeline
from haystack.utils import Secret
from haystack_integrations.components.websearch.xquik import XquikTweetSearch

search = XquikTweetSearch(
    api_key=Secret.from_env_var("XQUIK_API_KEY"),
    top_k=20,
    query_type="Latest",
)

pipeline = Pipeline()
pipeline.add_component("twitter_search", search)

result = pipeline.run(
    {
        "twitter_search": {
            "query": '"retrieval augmented generation" lang:en -filter:retweets'
        }
    }
)

documents = result["twitter_search"]["documents"]
links = result["twitter_search"]["links"]
```

Use `Latest` for chronological monitoring. Use `Top` for engagement-ranked discovery. Rankings can change, so store tweet IDs with every result.

### Build Focused Tweet Searches

Use a precise search query to keep RAG context focused.

| Search intent      | Query example                                |
| ------------------ | -------------------------------------------- |
| Exact phrase       | `"retrieval augmented generation"`           |
| Account posts      | `from:deepset_ai haystack`                   |
| Hashtag search     | `#haystack #rag`                             |
| Minimum engagement | `haystack min_faves:20`                      |
| Date window        | `haystack since:2026-07-01 until:2026-08-01` |
| Exclude reposts    | `haystack -filter:retweets`                  |
| Exact tweet        | A numeric tweet ID or X status URL           |

The API also supports structured search filters. Pass them through `extra_params` during initialization.

```python
search = XquikTweetSearch(
    top_k=50,
    query_type="Latest",
    extra_params={
        "language": "en",
        "mediaType": "links",
        "minFaves": 10,
        "replies": "exclude",
    },
)
```

Other filters cover authors, mentions, replies, reposts, quotes, URLs, and conversations. See the [tweet search API](/api-reference/x/search-tweets) for every supported filter.

Use `extra_params` only for stable request filters. Pass changing timestamps and cursors to each run.

## Choose a Search Window

Bound every scheduled retrieval with explicit timestamps. This prevents overlapping runs from scanning the same period.

```python
result = search.run(
    query="haystack agents",
    since_time="2026-07-31T00:00:00Z",
    until_time="2026-08-01T00:00:00Z",
)
```

Store the exact window beside the returned tweet IDs. Use non-overlapping windows for daily indexing. Allow a small overlap when late arrivals matter. Deduplicate the overlap by `Document.meta["id"]`.

## Fetch a Twitter User Timeline

Use `XquikUserTweetsFetcher` for `GET /x/users/{id}/tweets`. Pass a username or numeric X user ID.

```python
from haystack.utils import Secret
from haystack_integrations.components.websearch.xquik import (
    XquikUserTweetsFetcher,
)

timeline = XquikUserTweetsFetcher(
    api_key=Secret.from_env_var("XQUIK_API_KEY"),
    include_replies=False,
    include_parent_tweet=False,
)

result = timeline.run(user_id="deepset_ai")
documents = result["documents"]
```

Set `include_replies=True` for the account's replies. Turn on `include_parent_tweet=True` only for workflows needing reply context.

Choose tweet search for topics spanning many accounts. Choose timelines for one account's recent tweets. Choose REST for filters the components do not expose.

## Understand Haystack Document Fields

Each returned tweet becomes one Haystack `Document`. Tweet text becomes `Document.content`. Stable tweet attributes become metadata.

| Document field              | Stored tweet value                           |
| --------------------------- | -------------------------------------------- |
| `content`                   | Tweet text                                   |
| `meta.endpoint`             | `x.tweets.search` or `x.users.tweets`        |
| `meta.id`                   | Tweet ID                                     |
| `meta.url`                  | Canonical tweet URL                          |
| `meta.created_at`           | Tweet creation timestamp                     |
| `meta.lang`                 | Language code                                |
| `meta.conversation_id`      | Conversation ID                              |
| `meta.in_reply_to_id`       | Parent tweet ID                              |
| `meta.in_reply_to_user_id`  | Parent author ID                             |
| `meta.in_reply_to_username` | Parent author username                       |
| `meta.is_reply`             | Reply flag                                   |
| `meta.is_quote_status`      | Quote flag                                   |
| `meta.like_count`           | Like count                                   |
| `meta.retweet_count`        | Repost count                                 |
| `meta.reply_count`          | Reply count                                  |
| `meta.quote_count`          | Quote count                                  |
| `meta.view_count`           | View count                                   |
| `meta.bookmark_count`       | Bookmark count                               |
| `meta.author`               | Author ID, username, name, and verified flag |

Missing upstream fields stay absent. Do not treat missing metrics as zero. The `links` output contains each non-empty `meta.url` value.

## Build Reliable RAG Citations

Store tweet IDs before embedding tweet text. Keep canonical URLs beside every vector-store record. This preserves evidence after ranking, joining, or summarization.

```python
citation_rows = []

for document in documents:
    tweet_id = document.meta.get("id")
    tweet_url = document.meta.get("url")
    if tweet_id and tweet_url:
        citation_rows.append(
            {
                "tweet_id": tweet_id,
                "url": tweet_url,
                "created_at": document.meta.get("created_at"),
                "author": document.meta.get("author"),
            }
        )
```

Ask generators to cite only supplied URLs. Reject citations absent from the retrieved documents. Preserve `conversation_id` when answers summarize reply threads.

### Treat Tweet Text as Untrusted Context

Tweets can contain prompt injection, misleading instructions, and unsafe URLs. Never treat tweet text as a system instruction. Delimit retrieved tweets as quoted evidence. Never mix retrieved tweets with system instructions or tool permissions.

Apply these controls before generation:

1. Limit retrieval to the required topic and time window.
2. Keep tweet text separate from system and developer instructions.
3. Preserve tweet IDs, authors, timestamps, and URLs.
4. Require citations for factual claims derived from tweets.
5. Route sensitive conclusions to human review.

Engagement metrics do not prove accuracy. Use likes and reposts for ranking signals only.

## Paginate Without Duplicate Tweets

Both components return `has_more` and `next_cursor`. Treat cursors as opaque strings. Reuse the same query, ordering, limits, filters, and time window.

```python
search = XquikTweetSearch(top_k=100, query_type="Latest")
page = search.run(query="haystack ai")

documents_by_tweet_id = {}

while True:
    for document in page["documents"]:
        tweet_id = document.meta.get("id")
        if tweet_id:
            documents_by_tweet_id[tweet_id] = document

    if not page["has_more"] or not page["next_cursor"]:
        break

    page = search.run(
        query="haystack ai",
        cursor=page["next_cursor"],
    )

documents = list(documents_by_tweet_id.values())
```

Store each cursor checkpoint after persisting its documents. Resume with the saved cursor after a worker restart. Never decode or edit a cursor.

## Run Haystack Pipelines Asynchronously

Haystack 3 uses one `Pipeline` class for sync and async execution. Both Xquik components expose `run_async()`.

```python
import asyncio

from haystack import Pipeline
from haystack_integrations.components.websearch.xquik import XquikTweetSearch


async def search_tweets():
    pipeline = Pipeline()
    pipeline.add_component(
        "twitter_search",
        XquikTweetSearch(top_k=25, query_type="Latest"),
    )
    return await pipeline.run_async(
        {"twitter_search": {"query": "haystack agents"}}
    )


result = asyncio.run(search_tweets())
```

Use async execution inside web servers and concurrent ingestion workers. Use synchronous execution for scripts and scheduled batch jobs.

## Handle Every Documented Error

The integration raises `httpx.HTTPStatusError` after unsuccessful HTTP responses. Branch on the canonical status before retrying.

| Status | Tweet search meaning          | User timeline meaning         | Recommended action                       |
| ------ | ----------------------------- | ----------------------------- | ---------------------------------------- |
| `400`  | Missing or invalid query      | Invalid timeline input        | Fix the request. Do not retry unchanged. |
| `401`  | API key missing or invalid    | API key missing or invalid    | Add a valid API key.                     |
| `402`  | Credits or payment needed     | Credits or payment needed     | Check the account balance.               |
| `404`  | Not documented                | User not found                | Check the username or user ID.           |
| `424`  | X retrieval dependency failed | X retrieval dependency failed | Retry with bounded backoff.              |
| `429`  | Rate limit exceeded           | Rate limit exceeded           | Back off before retrying.                |
| `502`  | X retrieval error             | X retrieval error             | Retry up to the configured limit.        |

```python
import httpx

from haystack_integrations.components.websearch.xquik import XquikTweetSearch

search = XquikTweetSearch(top_k=20, max_retries=3)

try:
    result = search.run(query="haystack ai")
except httpx.HTTPStatusError as error:
    status = error.response.status_code
    if status in {400, 401, 402, 404}:
        raise RuntimeError(f"Fix Xquik request before retrying: HTTP {status}") from error
    if status in {424, 429, 502}:
        raise RuntimeError(f"Retry Xquik request with backoff: HTTP {status}") from error
    raise
```

Record status codes without storing API keys or full authorization headers. Cap retries to prevent unbounded agent loops.

## Haystack Component or Direct REST API

Components work best when your workflow already uses `Document` objects. They normalize tweet text, metadata, URLs, and pagination.

Use the direct Xquik REST API when you need:

- Follower or following exports
- Tweet replies, quotes, or reposts as separate response shapes
- Lists, communities, media, trends, or monitors
- Write actions with explicit approval
- Query options absent from the Haystack component interface

Both approaches use the same public Xquik contracts. Keep the component scope to tweet search and user timelines.

## Migrate to Haystack 3

Haystack 3 replaces `AsyncPipeline` with one `Pipeline` class. Change `AsyncPipeline()` to `Pipeline()`. Then call `await pipeline.run_async(...)` for concurrent execution.

Haystack 3 also produces deterministic `Document.id` values from canonical metadata. Continue using `meta.id` as the tweet identity. Tweet IDs remain stable across embedding and metadata changes.

Pin `haystack-ai==3.0.0` while validating your existing generators, stores, and custom components. Check the [official Haystack 3 migration guide](https://docs.haystack.deepset.ai/docs/migration) for other changes.

## Common Haystack Twitter API Questions

### What Is Haystack AI?

Haystack organizes search, RAG, and AI agents inside Python pipelines. A pipeline links search results to generation, storage, and evaluation.

### How Does the Twitter API Search Tweets?

The Twitter API search route receives a query, filters, ordering, and optional cursor. Xquik returns normalized tweets, pagination fields, and canonical URLs for citations.

### What Is a Twitter Search API Python Workflow?

Install both packages, load the API key, and create `XquikTweetSearch`. Run the component with a query, then process its `documents`, `links`, and cursor fields.

### How Does an API Twitter Search Workflow Preserve Cursors?

Store `next_cursor` after every successful page. Reuse the same filters and ordering. Pass only the saved cursor when fetching the next page.

### How Does the Twitter API Search Tweets by Keyword?

Pass keywords, phrases, hashtags, account operators, or structured filters. Use `Latest` for chronological results and `Top` for engagement-ranked results.

### Haystack AI vs LangChain: Which Fits Twitter RAG?

Choose Haystack when pipelines should exchange typed `Document` objects. LangChain fits applications already using its retrievers and tools. Both are frameworks for building AI applications with cited tweets.

### Where Is the Haystack AI GitHub Integration?

The [Xquik Haystack repository](https://github.com/Xquik-dev/xquik-haystack) contains the package and offline tests. You get two read-only components. The package never starts a tool called by a model.

### Can a Haystack AI Agent Publish Tweets?

No. This integration only reads tweet searches and user timelines. The separate write API handles approved publishing requests.

### Does This Require a Haystack Enterprise Platform?

No. The integration runs inside open-source Haystack pipelines. Those pipelines run in your existing Haystack environment.

### How Many Tweets Can One Search Return?

Set `top_k` to control the requested number of tweets per page. Continue with `next_cursor` when `has_more` is true.

### Can Haystack Search Twitter Tweets Without the Official X API SDK?

Yes. `XquikTweetSearch` calls Xquik's REST API and returns Haystack documents. You do not need the official X SDK.

### How Do I Search a User's Tweets in a Haystack Pipeline?

Use `XquikUserTweetsFetcher` with a username or numeric user ID. Enable replies only when your retrieval task needs conversations.

### How Do I Cite Tweets in a RAG Answer?

Store `Document.meta["url"]` with each embedded tweet. Require the generator to cite only retrieved URLs.

### Should a Twitter RAG Pipeline Use `Latest` or `Top`?

Use `Latest` for monitoring and fresh events. Use `Top` for engagement-ranked discovery. Save tweet IDs because rankings can change.

### How Do I Prevent Duplicate Tweets During Pagination?

Deduplicate on `Document.meta["id"]`. Keep the request unchanged and pass only the returned cursor.

### Can the Haystack Integration Scrape Followers or Publish Tweets?

No. The package exposes tweet search and user timeline components. Use the dedicated Xquik APIs for followers, following, replies, and writes.

### Can I Use Tweet Text as Trusted Instructions for an Agent?

No. Treat tweet text as untrusted evidence. Never mix it with system instructions or tool permissions.
